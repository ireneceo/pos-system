### 팀원이 판정문과 다르게 한 것 8건 — 전부 **수용**
1. 정산서 총액을 `finalizeInvoice` 로 안 맞춤 → **맞는 판단.** 그 함수는 청구서 «줄 항목» 합으로 소계를 내는데 정산서엔 줄 항목이 없어 0 이 됐을 것(제가 함수 실물로 확인).
2. 칸 2개를 전용 마이그로 추가 → **맞는 판단.** 운영 배포의 sync 는 안전모드라 칸을 안 넣음(09-10 사고 기억). 배포 목록에 등록돼 있음.
3. 오너가 등록한 외부 업체는 월별 못 켬(400) → **수용.** 계약 행이 오너 것이라 자동 발행기·월결제 판정이 매장을 못 찾는 구조. 운영에 해당 업체 0곳. 생기면 «매장에서 등록» 안내가 뜸.
4. 월 정산서 메일 «대조용» 한 줄이 영어만 → **수용.** 그 메일 자체가 원래 영어 고정(번역 틀이 없음).
5. SW 버전 미상승 → 배포 묶음에서 올림(조건 ①).
6. 직원식 배지가 **발주 상세·담기·보고서**에만 있고 **발주 목록 머리·수령 창·발주서 PDF/공유 메시지** 엔 없음 → **배포를 막을 사유는 아님.** 목적(직원식 비용을 따로 보는 것)은 상세·보고서로 이미 됨. 아래 «Irene 정할 것» 1건.
7. 금고 차액 줄은 현금 + 매장이 낼 때만 → **맞는 판단**(금고는 매장 것).
8. 고장주입 ③ 원안(«상태 동기화 빼면 ⑥ 실패»)이 성립 안 함 → 설명이 맞음(자식은 결제 루프에서 이미 결제됨으로 바뀌고, 동기화 호출은 «정산서 상태 바꾸는 모든 길이 부른다» 규칙 유지용 안전망). 대체 주입(«자식 발주 결제 루프 제거 → ⑥ 실패»)이 같은 것을 증명함.
