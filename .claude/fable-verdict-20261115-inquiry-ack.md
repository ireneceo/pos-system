# Fable 완료 검증 — 시스템 문의 접수 확인 (2026-11-15)

> 대상: `.claude/fable-design-20261115-inquiry-autoreply-board.md` §2-3 · Irene «권고대로 진행해 줘.»
> 종류: `gate`(외부 발송). 판정: **PASS — 검증 중 결함 1건을 찾아 한 줄 고친 뒤 통과.**

## 판정

접수 확인은 설계 범위대로 들어갔고, 보내면 안 되는 경우가 하나 더 있어 막았다. 다음 배포에 나가도 된다.

## 검증 중 찾아 고친 것 (1건 — Fable 이 직접 고침)

- **관리자가 고객 대신 만든 문의에도 접수 확인이 나갔다.** 관리자 화면(`dev-frontend/src/pages/Admin/SystemInquiryPage.tsx` 593행)은 고객 이름으로 문의를 만들 수 있고, 그때 문의 주인은 고객이 된다. 제외 조건은 «주인이 System Admin» 만 봐서, 고객은 쓰지도 않은 글을 «보내 주신 내용» 으로 인용한 메일을 받게 된다. 설계의 «우리 쪽이 만든 문의는 보내지 않는다» 에 어긋난다.
- 고친 곳: `dev-backend/routes/support-tickets.js` — 조건을 `req.user.role !== 'System Admin' && shouldAcknowledgeTicket(ticket)` 로. 시험 1건 추가(`tests/inquiry-ack.test.js`).
- 반증: 시험을 먼저 넣고 고치기 전 코드로 돌려 **1 실패**(접수 확인 1건 나감) 확인 → 고친 뒤 10/10.
- 이 수정은 Fable 이 쓰고 Fable 이 검증했다(따로 본 눈 없음). 한 줄 조건이라 그대로 두었다.

## 설계와 다른 점 (받아들임)

- 설계 §2-3 은 «앱 알림 + 메일» 이라 썼지만 `sendWithNativeAddressee` 는 **메일만** 보낸다(다른 문의 알림도 같다). 설계 글이 틀렸다. 접수 확인은 메일만 나간다 — 문의는 고객 화면 목록에 바로 보이므로 앱 알림을 따로 만들지 않는다.
- 완료 기준 6 «health-check 에 1·2번 상시 검사» 는 규칙 함수·연결·문구 계약으로 들어갔고, 라우트 실호출은 jest 에 있다. jest 는 배포 게이트 밖이다 — 규칙 함수가 깨지면 health-check 가 잡지만, 라우트의 대리 작성 조건은 jest 만 잡는다.
