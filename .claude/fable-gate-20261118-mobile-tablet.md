## 2. 고쳐야 하는 것

### ① [새로 생긴 가림] 프린터 알림이 하위 메뉴 창의 아래 항목을 덮는다
- 알림의 왼쪽 기준을 본문 칸으로 옮기면서(B2), 사이드바 «설정»·«소통» 처럼 아래쪽 메뉴를 눌러 뜨는 **하위 메뉴 창의 아랫부분 위에 알림이 올라앉는다.**
- 실측(매장 관리자 · 손가락): 1024×768 과 1180×820 에서 «설정» 창의 «프린터» 를 누르면 **알림이 대신 눌려** 설정으로 못 간다(«매장 설정»·«회사 정보» 는 정상 이동). 1180 이상에서는 큰 상자(440×116)라 2~3항목이 덮인다.
- 설계 F8(«떠 있는 띠가 누르는 요소를 덮음») 불합격. 팀원 측정기는 창을 연 상태를 안 쟀다.
- **지시:** 알림 파일(`PrinterSetupGapBanner` — 보호 아님) 안에서만 푼다. 합격 조건 = 하위 메뉴 창을 연 상태에서 창의 모든 항목 위에 알림 0 · 사이드바 아래(매장 전환·내 정보)도 안 덮음 · POS·주방 화면에서는 지금처럼 보임.

### ② [합격으로 잘못 보고됨] 태블릿에서 1단 메뉴를 누르면 창이 내용 위에 남는다 (N2)
- 실측: «운영» 을 누르면 인보이스로 **이동하면서** 하위 메뉴 창이 열리고, **8초 뒤에도 그대로 남아** 화면의 «주간·월간·연간» 버튼을 덮는다. 다른 곳을 눌러야 닫힌다.
- 설계 F3 에 «누른 뒤 메뉴 창이 내용 위에 남아 가림 = 불합격» 이라고 적혀 있다. 팀원은 «이동 + 창 열림 → 합격» 으로 보고 M6 을 건너뛰었다. **불합격이 맞고 M6(손가락일 때는 이동하지 않고 창만 연다 · 항목을 누르면 이동하고 닫힘)을 해야 한다.**
- 팀원의 원래 측정(`n2.out`)은 흔들렸다 — 매장 가로 화면에서 «상품·운영·리포트» 가 «아무 일 없음» 으로 찍혔고, 아래에 가려진 3개(팀 및 마케팅·소통·설정)는 아예 안 눌렀다. 누르는 위치가 화면이 덜 뜬 상태에서 잡혀 «매장 전환» 을 누른 줄도 있다. 내가 위치를 보정해 다시 재니 창은 6개 역할·폭 조합에서 다 열리고 항목 이동도 된다(①의 덮임 제외).
- 덧붙여: 이번에 ≤1024 에서 «»»(하위 메뉴 고정) 버튼을 숨겼으므로 그 폭에서는 이 창이 하위 메뉴로 가는 **유일한 길**이다. 그래서 ①②가 더 중요해졌다.
- «설정» 창은 항목 14개 중 6개만 한 번에 보이고 나머지는 창 안에서 밀어야 한다. 창 안 밀기는 코드상 되게 되어 있으나 손가락 흉내로는 확인하지 못했다(**확인 못 함** — 태블릿 실기기).

## 4. Fable 권고 — «MainLayout 지문 다시 등록을 해도 되는가»

**Fable 권고: 지금은 등록하지 않는다. ②를 고친 뒤 한 번에 등록한다.**

- 이유 1 — **인쇄 때문이 아니다.** 지금 상태의 MainLayout 변경은 인쇄에 닿지 않는다는 것을 줄 단위와 실측으로 확인했다. 인쇄 안전만 보면 지금 등록해도 된다.
- 이유 2 — **이 파일을 한 번 더 고쳐야 한다(M6).** 지금 등록하면 며칠 안에 같은 파일을 또 등록하게 된다. 인쇄 보호 지문은 «등록 = 이 상태가 정답» 이라는 뜻이라, 고칠 것이 남은 상태를 정답으로 박지 않는 편이 맞다. 그사이 지문 검사가 빨간 것은 «아직 안 끝났다» 는 정확한 표시다.
- 이유 3 — 그동안 운영 배포는 지문 검사가 막는다. 이 묶음은 어차피 ①②③ 뒤에 나가야 하므로 손해가 없다.

**②까지 끝난 뒤의 등록 조건(전부 기계로 갈린다 — 이 조건이 다 맞으면 Fable 을 다시 부르지 않고 등록해도 된다는 것이 내 권고):**
1. MainLayout 변경이 지금의 15군데 + «1단 메뉴 누름 처리 한 곳(M6)» + «폰 머리줄 모양 정의» 뿐 · 인쇄 관련 줄 구간(인쇄 설정 읽기 ~ `_printPollFn`) 변경 0.
2. 지문 검사에서 바뀐 파일이 MainLayout 1개뿐.
3. 매장 38 화면 60초 인쇄 대기 조회 12~14회 · 간격 5초.
4. 인쇄 계약 검사(health-check 인쇄 묶음)에서 지문 항목 말고 실패 0.
5. 매장·브랜드 × 1024×768·1180×820·820×1180 손가락 측정: 1단을 누르면 **이동 없이** 창이 열림 · 창의 모든 항목이 눌려 이동 · 이동 뒤 창 닫힘 · 알림에 덮인 항목 0. 마우스(1366)에서는 지금과 같은 동작.
6. 전체 화면 열기 크래시 0.

**Irene 이 ②(M6)를 하지 않기로 정하면** — 지금 상태 그대로 등록해도 인쇄에는 문제없다는 것이 내 판단이다(위 §1). 그 경우 ①만 고치고 등록.

## 2. 알고 계실 것 (막지는 않음)

1. **«120px 넘는 표 25 → 3» 은 «표가 낮아졌다» 는 뜻이 아니다.** 14개 표가 카드로 바뀌어 «표» 로 세지 않게 된 것이다. 카드 한 장은 184~256px 로 예전 표 한 줄(129~230px)과 비슷하거나 더 높다 — 아이패드 가로 한 화면에 3건쯤 보인다. 대신 날짜가 네 줄로 쪼개지거나 버튼이 세로로 쌓이던 것이 없어지고 칸마다 이름이 붙어 **읽기는 분명히 나아졌다**(사진 확인). 1차에 내가 처방한 방법 그대로이므로 합격으로 본다. 한 화면에 더 많은 줄이 필요하면 다음 묶음에서 카드 칸 수를 조정한다.
2. **1281~1366 폭(아이패드 프로 가로·작은 노트북)은 1차와 같다.** 120px 넘는 표 24개 · 발주 내역 187~230px · 버튼 4줄 쌓임. 옆으로 밀림은 0. 1차 목표를 1180 으로 잡았으므로 이번엔 막지 않는다 — 리스트업 «남음» 에 이미 적혀 있다. 다음 묶음 1순위(날짜 칸 합치기 · «⋯ 더보기»).
3. **«설정» 창은 14개 중 6개만 보이는데 «아래에 더 있다» 는 표시가 없다.** 밀면 나오지만 «프린터» 에서 딱 끊겨 보여 모를 수 있다(사진 `menu_restaurant_1180.png`). 다음 묶음에 창 아래 흐림 표시.
4. **지금 개발서버 화면은 «빌드 4» 그대로가 아니다.** 빌드 4 뒤 오늘 03:33 에 다른 작업방(61a8eab9 — 판매 주문 «확정» 상태색)이 같은 폴더에서 한 화면을 더 고치고 다시 빌드했다. 내 측정은 그 최신 화면에서 했고 결과는 위와 같다. 다만 «전체 화면 열기 크래시 0» 기록은 빌드 4 것이다 — 운영 배포 때 배포 검사가 최신 화면으로 다시 돈다.
- 덧붙임: 태블릿 가로 카드 모양 정의 2줄이 새 문법(`:has`)을 쓴다. 2022년 가을 이전 브라우저에서는 카드 바깥 테두리가 한 겹 더 보이는 정도(겹침·가림 없음)라 그대로 둔다.
