## 1. 결론

1. **막힌 원인은 계정이 아니라 내 11-10 설계의 N 상태 잠금이다.** 설계 §2-3 이 «아직 안 정함(N) = 잠김» 으로 정했고, 6.18 이 나가면서 운영의 모든 기존 매장이 N 에서 시작했다. 즉 6.18 배포가 모든 매장 관리자의 프린터 칸을 잠갔다. «배포해도 안 된다» 는 이 설명과 맞는다(배포가 고친 게 아니라 배포가 잠갔다).
2. **N 상태는 관리자에게 바로 열어 준다(6.18 이전 동작으로 되돌림).** Irene 의 11-10 요구는 «한 디바이스에서, 다른 곳에서 안 하게, 하려면 확인하고» 다. 지켜야 할 것은 «정해진 기기가 있는데 다른 기기에서 바꾸는 것» 이고, 정해진 기기가 없는 N 에는 «다른 곳» 이 없다. N 잠금은 요구에 없던 것을 내가 얹은 것이고, 급한 순간에 관리자를 세운다. 설계 오류로 판정하고 고친다.
3. **첫 저장 때 자동 지정은 하지 않는다.** 관리자가 집 노트북에서 칸 하나만 바꿔도 그 노트북이 설정 기기가 되어 매장 기기가 «다른 기기» 로 잠긴다. 지정 창의 경고(인쇄하는 기기가 아님 · 브라우저 태블릿)도 건너뛰게 된다. 지정은 지금처럼 버튼으로 명시적으로만 한다. 안 정한 매장은 6.18 이전과 같은 보호 수준일 뿐 나빠지지 않는다.
4. **kdineipc1 계정 데이터는 바꾸지 않는다.** 운영 읽기: users.id 19 = Restaurant Admin. 11-12 운영 로그: 이 계정의 09:37 저장이 매장 28 printer_settings 를 실제로 바꿨다(서버가 관리자로 처리). 서버는 N 상태 관리자 저장을 이미 허용한다(`resolvePrinterWrite` → `no_setup_device`). 운영 쓰기 0.
   - 확인 불가: 매장 28 모자(user_contexts) 행의 역할은 오늘 재확인 실패. 판별법은 §5.
