## Fable 이 직접 한 것

2. **V6 전 매장 전후 비교(개발 DB 33개 매장)** — 받는 사람이 달라진 매장 2곳뿐: 매장 38 에 user 2001 추가(매장 모자) · 매장 158 에서 user 369 빠짐(꺼진 계정). 나머지 31곳 동일. → «모자 추가 · 꺼진 계정 제외» 외 변화 없음.
3. **진짜 로그인 토큰** — 팀원 시험은 손으로 만든 토큰이었음. 데모 빠른 로그인으로 받은 실제 토큰(매장 38)으로 소켓을 붙여 38 주문 카드 옴 / 39 화면엔 안 옴 확인. 토큰 발급 5곳 모두 `restaurant_id` 칸을 가짐(읽기).
4. **V7 예약(요청서 «확인 불가» → 확인함)** — 매장 39 예약 생성·상태 변경 실호출: 모자 관리자에게 기록 남음 · 카드는 39 화면만, 38 화면 0.
5. **V3 새로고침 없는 전환(요청서 «확인 불가» → 확인함)** — 실브라우저: 38 대시보드(38 카드 뜸 · 39 카드 안 뜸) → 선택 화면에서 39 클릭 → 전체 새로고침 0회 · 알림 소켓이 새 토큰(39)으로 다시 붙음 · 39 주문 카드 뜸 · 새 38 주문 카드 안 뜸 · 페이지 오류 0. 12/12.
6. **재실행** — 팀원 실호출 14/14 · 상시 검사 «매장 알림» 2/2(건너뜀 아님) · health-check 전체 487건.
7. **배포 안전성** — 배포 스크립트는 마이그(등록됨·멱등·expandEnum)를 운영 백엔드 재시작 **앞**에 돌림. 새 칸은 NULL 허용 추가라 옛 코드와 공존, 되돌려도 무해. 개발 DB 칸·ENUM 실제 반영 확인.

## 검증 중 발견 → Fable 이 한 줄 고침
- **증상**: 매장별 끄기를 누른 뒤(조용한 시간을 한 번도 안 정한 사람) 같은 화면에서 «조용한 시간» 을 켜면 저장이 400 으로 조용히 실패. 화면은 켜진 것처럼 보임.
- **원인**: 새 끄기 동작만 저장 응답으로 화면 상태를 통째로 갈아 끼우는데, 저장 응답의 `muted_hours` 가 빈 값(null)이었음(조회는 기본값을 줌).
- **고침**: `routes/push.js` PUT 응답에 조회와 같은 기본값(1줄 + 주석). 재현 → 수정 뒤 200 확인. 화면 빌드 불필요.
