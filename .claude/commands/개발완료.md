# 개발 완료 명령어

이 명령어는 개발 세션을 마무리할 때 사용합니다.

---

## 필수 수행 (건너뛰기 금지)

**Claude는 반드시 아래 단계를 순서대로 실행해야 합니다. 어떤 단계도 생략하면 안 됩니다.**

---

### 1단계: 오늘 작업 내용 수집 (Bash 실행 필수)

```bash
cd /var/www && git diff --name-only HEAD~5
```

이 명령어로 최근 변경된 파일 목록을 확인하고, 현재 세션에서 수행한 작업을 정리합니다.

---

### 2단계: DEVELOPMENT_PLAN.md 히스토리 추가 (Edit 도구 필수 사용)

**반드시 Edit 도구로 `/var/www/DEVELOPMENT_PLAN.md` 파일을 수정해야 합니다.**

#### 2-1. 최종 업데이트 날짜 변경

파일 상단의 날짜를 오늘 날짜로 변경:
```
> **최종 업데이트:** 2026-XX-XX
```

#### 2-2. 완료된 작업 섹션 추가

**"🚀 서비스 오픈 준비 로드맵" 섹션 바로 위에** 새 섹션 추가:

```markdown
## ✅ 완료: [작업 제목] (YYYY-MM-DD)

### 완료된 작업

| 작업 | 설명 | 상태 |
|------|------|:----:|
| [작업1] | [설명] | ✅ 완료 |
| [작업2] | [설명] | ✅ 완료 |

### 수정된 파일
- `path/to/file1.tsx`
- `path/to/file2.js`

---
```

#### 2-3. 로드맵 상태 업데이트 (해당되는 경우)

오픈 준비 Phase A~C 또는 8단계 Phase 중 완료된 항목이 있으면 상태를 ✅로 변경

---

### 3단계: session-state.md 업데이트 (Write 도구 필수 사용)

**반드시 Write 도구로 `/var/www/.claude/session-state.md` 파일을 덮어써야 합니다.**

```markdown
## 현재 작업 상태
**마지막 업데이트:** [오늘 날짜]
**작업 상태:** 완료

### 진행 중인 작업
- 없음

### 완료된 작업 (이번 세션)
- [오늘 완료한 작업 1]
- [오늘 완료한 작업 2]

### 다음 할 일
- [다음 예정 작업]

---

## 서버 재시작 후 복구 가이드

새 Claude 세션 시작 시 아래 내용을 붙여넣으세요:

\`\`\`
이전 세션에서 진행하던 작업을 이어서 하고 싶어.
/var/www/.claude/session-state.md 파일 읽어줘.
\`\`\`
```

---

### 4단계: 업데이트 검증 (Read 도구 필수 사용)

**반드시 Read 도구로 업데이트된 내용을 확인해야 합니다:**

1. `/var/www/DEVELOPMENT_PLAN.md` 상단 50줄 읽기 → 오늘 날짜와 새 섹션 확인
2. `/var/www/.claude/session-state.md` 읽기 → 오늘 작업 목록 확인

**검증 실패 시 2~3단계 다시 수행**

---

### 5단계: Git 커밋 및 푸시 (Bash 실행 필수)

```bash
cd /var/www && git add -A && git status
```

변경사항 확인 후 커밋:

```bash
git commit -m "$(cat <<'EOF'
chore: Auto-commit YYYY-MM-DD HH:MM:SS

[오늘 작업 요약]
- 작업1
- 작업2

Co-Authored-By: Claude Opus 4.5 <noreply@anthropic.com>
EOF
)"
```

푸시:
```bash
git push origin main
```

---

### 6단계: 백업 생성 (Bash 실행 필수)

```bash
BACKUP_DIR="/var/www/backups/dev-daily/$(date +%Y%m%d)"
mkdir -p "$BACKUP_DIR"

tar -czf "$BACKUP_DIR/dev-backend.tar.gz" \
  --exclude='node_modules' \
  -C /var/www dev-backend

tar -czf "$BACKUP_DIR/dev-frontend.tar.gz" \
  --exclude='node_modules' \
  --exclude='build' \
  -C /var/www dev-frontend

# 7일 이상 된 백업 정리
find /var/www/backups/dev-daily -type d -mtime +7 -exec rm -rf {} + 2>/dev/null

echo "백업 완료: $BACKUP_DIR"
```

---

### 7단계: 완료 보고

사용자에게 다음 형식으로 보고:

```
## 개발 완료 보고

### 오늘 완료한 작업
- [작업1]
- [작업2]

### 업데이트된 문서

- session-state.md

### Git
- 커밋: [해시]
- 푸시: 완료

### 백업
- 위치: /var/www/backups/dev-daily/YYYYMMDD/

### 다음 작업
- [다음 예정 작업]
```

## 체크리스트 (모든 항목 완료 필수)

| # | 단계 | 도구 | 완료 |
|:-:|------|------|:----:|
| 1 | git diff로 변경 파일 확인 | Bash | ☐ |
| 2 | DEVELOPMENT_PLAN.md 날짜 변경 | Edit | ☐ |
| 3 | DEVELOPMENT_PLAN.md 히스토리 추가 | Edit | ☐ |
| 4 | session-state.md 업데이트 | Write | ☐ |
| 5 | 업데이트 내용 검증 | Read | ☐ |
| 6 | Git 커밋 | Bash | ☐ |
| 7 | Git 푸시 | Bash | ☐ |

---

## 주의사항

1. **"분석 중...", "업데이트 중..." 같은 말만 하고 실제 도구를 사용하지 않으면 안 됨**
2. **Edit/Write 도구 사용 없이 "업데이트했습니다"라고 하면 거짓말임**
3. **검증 단계(4단계)에서 업데이트가 안 됐으면 다시 해야 함**
4. **운영서버 배포는 별도 `/배포` 명령어 사용**
