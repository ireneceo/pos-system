# 개발 완료 명령어

이 명령어는 개발 세션을 마무리할 때 사용합니다.

---

## 필수 수행 (건너뛰기 금지)

**Claude는 반드시 아래 단계를 순서대로 실행해야 합니다. 어떤 단계도 생략하면 안 됩니다.**

---

### 1단계: 오늘 작업 내용 수집 (Bash 실행 필수)

```bash
cd /var/www && git diff --name-only HEAD~5
```

이 명령어로 최근 변경된 파일 목록을 확인하고, 현재 세션에서 수행한 작업을 정리합니다.

---

### 2단계: DEVELOPMENT_PLAN.md 히스토리 추가 (Edit 도구 필수 사용)

**반드시 Edit 도구로 `/var/www/DEVELOPMENT_PLAN.md` 파일을 수정해야 합니다.**

#### 2-1. 최종 업데이트 날짜 변경

파일 상단의 날짜를 오늘 날짜로 변경:
```
> **최종 업데이트:** 2026-XX-XX
```

#### 2-2. 완료된 작업 섹션 추가

**"🚀 서비스 오픈 준비 로드맵" 섹션 바로 위에** 새 섹션 추가:

```markdown
## ✅ 완료: [작업 제목] (YYYY-MM-DD)

### 완료된 작업

| 작업 | 설명 | 상태 |
|------|------|:----:|
| [작업1] | [설명] | ✅ 완료 |
| [작업2] | [설명] | ✅ 완료 |

### 수정된 파일
- `path/to/file1.tsx`
- `path/to/file2.js`

---
```

#### 2-3. 로드맵 상태 업데이트 (해당되는 경우)

오픈 준비 Phase A~C 또는 8단계 Phase 중 완료된 항목이 있으면 상태를 ✅로 변경

### 3단계: 관련 Docs 문서 검토 및 업데이트 (Read + Edit 도구 필수 사용)

**오늘 작업과 관련된 문서가 있으면 반드시 업데이트해야 합니다.**

#### 3-1. 변경 파일 기반 관련 문서 자동 매칭

오늘 수정한 파일/기능을 아래 매핑 테이블과 대조하여, 관련 문서를 Read 도구로 읽고 업데이트 필요 여부를 판단합니다.

| 변경 영역 | 관련 문서 |
|-----------|----------|
| 역할/권한 변경 | `/var/www/docs/ROLES_AND_PERMISSIONS.md` |
| 인보이스/결제 | `/var/www/docs/INVOICE_SYSTEM.md`, `/var/www/docs/PAYMENT_SYSTEM_PLAN.md`, `/var/www/docs/BILLING_SYSTEM_INTEGRATION_PLAN.md` |
| DB 스키마 변경 | `/var/www/docs/SCHEMA-MIGRATION-GUIDE.md` |
| UI 컴포넌트/스타일 변경 | `/var/www/dev-frontend/UI_DESIGN_GUIDE.md` |
| Modal/Form 변경 | `/var/www/dev-frontend/src/components/UI/README.md` |
| Select 컴포넌트 | `/var/www/dev-frontend/src/components/UI/SELECT_COMPONENT_GUIDE.md` |
| 필터 UI 변경 | `/var/www/dev-frontend/FILTER_STYLE_GUIDE.md` |

| CLAUDE.md/워크플로우 | `/var/www/CLAUDE.md` |

#### 3-2. 검토 및 업데이트 절차

1. 매칭된 문서를 **Read 도구로 읽기**
2. 오늘 변경사항과 문서 내용이 **불일치하는 부분** 찾기
3. 불일치가 있으면 **Edit 도구로 문서 업데이트**
4. 불일치가 없으면 "검토 완료, 업데이트 불필요" 기록

#### 3-3. 업데이트 판단 기준

- **업데이트 필요**: 새 기능 추가, 기존 동작 변경, API 스펙 변경, DB 컬럼 추가/변경
- **업데이트 불필요**: 버그 수정(문서에 영향 없음), 스타일만 변경, 리팩토링
- **판단 애매**: Irene에게 질문

#### 3-4. Memory 파일 업데이트

오늘 작업 중 반복 패턴이나 중요한 아키텍처 결정이 있었으면:
- `/home/irene/.claude/projects/-var-www/memory/MEMORY.md` 업데이트 검토
- 기존 내용과 중복되지 않게, 새로운 정보만 추가

### 3.5단계: CHANGELOG.md 업데이트 (Edit 도구 필수 사용)

**반드시 Edit 도구로 `/var/www/CHANGELOG.md` 파일의 `[Unreleased]` 섹션을 업데이트합니다.**

#### 규칙
1. `[Unreleased]` 섹션 아래에 **오늘 날짜 헤더** (`### YYYY-MM-DD`)가 없으면 추가
2. 오늘 날짜 헤더 아래에 완료된 작업을 **한 줄씩** 추가 (`- 작업 내용`)
3. 이미 같은 날짜 헤더가 있으면 그 아래에 추가 (중복 날짜 만들지 않음)
4. 기존 내용은 수정/삭제하지 않음
5. 너무 세부적인 내용은 제외 — **사용자가 공지에 쓸 수 있는 수준**으로 작성

#### 예시
```markdown
## [Unreleased] — 미배포 (개발서버만)

### 2026-04-08
- 계약관리 UI 개선 (StatCard 색상, 필터 통합)
- Settings AutoSaveField 적용
```

### 5단계: 업데이트 검증 (Read 도구 필수 사용)

**반드시 Read 도구로 업데이트된 내용을 확인해야 합니다:**

### 6단계: Git 커밋 및 푸시 (Bash 실행 필수)

```bash
cd /var/www && git add -A && git status
```

변경사항 확인 후 커밋:

```bash
git commit -m "$(cat <<'EOF'
chore: Auto-commit YYYY-MM-DD HH:MM:SS

[오늘 작업 요약]
- 작업1
- 작업2

Co-Authored-By: Claude Opus 4.5 <noreply@anthropic.com>
EOF
)"
```

푸시:
```bash
git push origin main
```

### 7단계: 백업 생성 (Bash 실행 필수)

```bash
BACKUP_DIR="/var/www/backups/dev-daily/$(date +%Y%m%d)"
mkdir -p "$BACKUP_DIR"

tar -czf "$BACKUP_DIR/dev-backend.tar.gz" \
  --exclude='node_modules' \
  -C /var/www dev-backend

tar -czf "$BACKUP_DIR/dev-frontend.tar.gz" \
  --exclude='node_modules' \
  --exclude='build' \
  -C /var/www dev-frontend

# 7일 이상 된 백업 정리
find /var/www/backups/dev-daily -type d -mtime +7 -exec rm -rf {} + 2>/dev/null

echo "백업 완료: $BACKUP_DIR"
```

## 주의사항

1. **"분석 중...", "업데이트 중..." 같은 말만 하고 실제 도구를 사용하지 않으면 안 됨**
2. **Edit/Write 도구 사용 없이 "업데이트했습니다"라고 하면 거짓말임**
3. **검증 단계(4단계)에서 업데이트가 안 됐으면 다시 해야 함**
4. **운영서버 배포는 별도 `/배포` 명령어 사용**
5. **버전(session-state.md의 `**버전:**`)은 절대 변경하지 않는다. 버전은 `/배포` 시에만 올린다.**
