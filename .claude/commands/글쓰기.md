## ★ 사용자 환경 / 권한 모델 (모든 단계 공통)

이 스킬은 **어떤 OS 사용자(irene/lua/...)가 실행해도 동일하게 작동**한다. 도메인 권한은 application-level RBAC(System Admin) 으로만 통과시킨다. **`.env` / `require('./models/...')` / `require('dotenv').config()` 같은 DB 직접 접근 패턴 절대 금지.**

이유: 백엔드는 `irene`으로 가동 중 → `.env`가 600. 다른 OS 사용자는 못 읽음. 이 스킬을 lua 세션에서 돌리면 그 패턴은 항상 실패한다.

**모든 admin 작업은 HTTP API 호출만 사용**한다 (login → 토큰 → admin endpoint).

### 자격증명 (자기 세션에서 한 번만)

```bash
node /var/www/dev-backend/scripts/setup-creds.js
```

→ SA username/password TTY 입력 → /api/auth/login 검증 통과 시 `~/.purple-pos/creds.json` 자동 작성 (chmod 600).
**틀린 자격증명은 거절되어 파일이 안 만들어진다** (디버깅 단순).

또는 `PURPLE_USER` / `PURPLE_PASS` 환경변수.

### 표준 헬퍼

| 스크립트 | 용도 |
|---|---|
| `node /var/www/dev-backend/scripts/setup-creds.js` | 자격증명 한 번 setup (TTY) |
| `node /var/www/dev-backend/scripts/sa-token.js` | SA JWT 한 줄 출력 (모든 admin curl/fetch 인증용) |
| `node /var/www/dev-backend/scripts/blog-bulk-publish.js <payload.json>` | bulk 발행 (login + bulk POST) |

자격증명이 없거나 SA가 아니면 명확히 에러 후 종료한다. 추측·우회 금지.

## 0단계: ★ 타깃 (Persona) 먼저 결정 — 절대 생략 금지

> Irene 이 **어떤 역할을 위해 쓰는지** 먼저 정해야 한다. 타깃 없이 트렌드/매트릭스로 들어가면 주제가 6 페르소나에 뒤섞여 메시지가 흐려진다. 타깃이 정해져야 1단계 검색 쿼리 / 3단계 고객 DB 필터 / 4단계 매트릭스 row 모두 한 줄로 정렬된다.

**`/글쓰기` 호출 즉시 가장 먼저 `AskUserQuestion`** — 6 역할 + Auto 중 하나 선택받기:

```
question: "이번 글의 타깃은 누구예요?"
header: "타깃"
options:
  - Restaurant Admin (단일 매장 사장 / RA)  — 매트릭스 RA-1~5
  - Brand General (프랜차이즈 본부 / BG)    — 매트릭스 BG-1~4
  - Foodcourt General (푸드코트 운영 / FG)  — 매트릭스 FG-1~5
  - Owner (다지점 오너 / OW)                — 매트릭스 OW-1~5
  - Supplier (식자재 공급사 / SP)           — 매트릭스 SP-1~5
  - Staff (매장 직원 / ST)                  — 매트릭스 ST-1~5
  - Auto (매트릭스 발행 빈도 낮은 persona 자동 선택)
```

> AskUserQuestion 은 단일 select. 옵션 4개 한도라 "Restaurant Admin / Brand General / Foodcourt General / Auto + Others" 같이 4개로 묶고 "Other" 선택 시 free-text 로 Owner/Supplier/Staff 받기. 또는 두 번 나눠 묻기 (1차: 매장 운영자 / 본사·오너 / 공급망·직원 / Auto → 2차: 세부 선택).

선택값을 `PERSONA_CODE` 변수에 저장:
- `restaurant_owner` (단일 매장 사장 = RA)
- `brand_general` (BG)
- `foodcourt_general` (FG)
- `owner` (다지점 OW)
- `supplier` (SP)
- `staff` (ST)
- `auto` — 4단계에서 발행 이력 빈도 보고 가장 부족한 persona 자동 선택

선택 즉시 Irene 에게 확인 출력:
```
✓ 타깃: Restaurant Admin (단일 매장 사장)
→ 매트릭스 row RA-1~5 + 트렌드 / 고객 DB 모두 이 타깃에 한정해서 진행할게.
```

**`PERSONA_CODE` 가 정해지기 전에는 1단계로 진입하지 않는다.**

## 2단계: 내부 고객 대화 DB에서 실제 니즈 (PERSONA_CODE 매칭만)

> 추출된 티켓 중에서 **선택된 PERSONA_CODE 의 사용자 역할이 보고한 것** 만 필터해서 분석한다. 예: PERSONA_CODE=`brand_general` 이면 BG 가 연 SupportTicket / Brand 도메인 ContactInquiry 만.


```bash
cd /var/www/dev-backend && node -e "
const SupportTicket = require('./models/SupportTicket');
const ContactInquiry = require('./models/ContactInquiry');
const OperationTicket = require('./models/OperationTicket');
(async () => {
  const tickets = await SupportTicket.findAll({ limit: 30, order: [['createdAt','DESC']] });
  const inquiries = await ContactInquiry.findAll({ limit: 30 });
  const ops = await OperationTicket.findAll({ limit: 30 });
  console.log('=== Support Tickets ===');
  tickets.forEach(t => console.log('  [' + t.category + '] ' + t.subject));
  console.log('\\n=== Contact Inquiries ===');
  inquiries.forEach(i => console.log('  [' + i.inquiry_type + '] ' + (i.message||'').substring(0,100)));
  console.log('\\n=== Operation Tickets ===');
  ops.forEach(o => console.log('  [' + o.category + '] ' + o.subject));
  process.exit(0);
})();
"
```

반복되는 키워드/상황 3-5개 추출 → 주제 뱅크에 반영.

## 3단계: 매트릭스 + 트렌드 통합 → 주제 3건 제안 (PERSONA_CODE 한정)

> **선택된 PERSONA_CODE 의 row 안에서만 3건을 뽑는다.** Persona 는 고정 (RA / BG / FG / OW / SP / ST 중 하나), problem 만 다양화.
> 예: PERSONA_CODE=`restaurant_owner` 이면 후보 3건 모두 `RA-?` 셀에서 추출 (RA-1 operations / RA-2 finance / RA-5 mobile_orders 식으로 problem 만 분산).
> `auto` 인 경우: 발행 빈도 가장 낮은 persona 의 row 에서 3건.

### 평가 차원 (각 0-10, 총 60)

| 차원 | 설명 |
|------|------|
| **검색 수요** | 월간 검색량 추정 (WebSearch 결과의 노출도) |
| **경쟁 공백** | 경쟁사가 안 다루거나 약하게 다룬 주제 (+ 점수) |
| **PurpleHere 적합도** | 우리 기능이 실제 해결책인가 (높을수록 전환율 ↑) |
| **현지성** | 말레이시아 / 화교권 특화 관점 (지역 SEO 이점) |
| **AEO 가능성** | 질문형 + 숫자/팩트 기반 답변 가능 |
| **★ 매트릭스 결정성** | `docs/CONTENT_MATRIX.md` 의 셀에 매핑 가능 (페르소나 + problem 한 줄) |

### 매트릭스 우선 채택 원칙

`docs/CONTENT_MATRIX.md` 의 30셀 중 **아직 발행 안 된 셀**을 1순위로. 이미 발행한 셀은 6개월 cool-down (반복 노출 피로).

발행 이력 조회:
```bash
TOKEN=$(node /var/www/dev-backend/scripts/sa-token.js)
curl -s -H "Authorization: Bearer $TOKEN" \
  "http://localhost:3001/api/contents?type=blog&status=published&limit=50" \
  | python3 -c "
import json, sys
data = json.load(sys.stdin).get('data', {})
rows = data.get('rows') if isinstance(data, dict) else data
for it in rows or []:
    persona = it.get('target_persona', '?')
    problem = it.get('problem_category', '?')
    title = (it.get('translations', [{}])[0].get('title', ''))[:60]
    print(f'  [{persona}/{problem}] {title}')
" | sort -u
```

→ 발행 이력의 persona/problem 조합 빈도 확인 → 매트릭스 적용 안 된 셀 우선.

## 4.5단계: ★ 팩트 검증 (절대 생략 금지)

> **이 단계 없이 본문 생성으로 넘어가는 것은 금지된다.**
> 외부 LLM/검색 결과의 수치·날짜·법조항·세율은 모두 1차 출처로 교차 확인되어야 한다. 한 글에 잘못된 사실 1개가 들어가면 회사 신뢰가 깎이고, 마케팅 자산이 부채로 바뀐다.

### 검증 대상 (글에 인용될 모든 "사실")
- 정부 정책 / 법령 (LHDN, RMCD, MOF, BNM, KPDN, MITI, MOH 등)
- 시행일 / 마감일 / 유예기간 (Phase, deadline, grace period)
- 세율 / 임계값 / 면제 기준 (RM 금액, %, threshold)
- 벌금 / 처벌 조항 (Section 번호, RM 금액, 징역 기간)
- 통계 (시장 점유율, 거래량, 사용자 수)
- 제3자 가격 / 수수료 (DuitNow MDR, 카드사 fee)
- 경쟁사 기능 / 통계 — 직접 인용은 가급적 회피

### 1차 출처 우선순위 (반드시 .gov.my / .my 도메인을 먼저)
| 분야 | 1차 출처 |

| 결제 / 은행 | bnm.gov.my, paynet.my (DuitNow QR 통계) |
| 노동 / 인력 | mohr.gov.my (EPF, SOCSO, 최저임금) |
| 식품 안전 / 할랄 | jakim.gov.my (할랄 인증), moh.gov.my |
| 통계 | dosm.gov.my (Department of Statistics Malaysia) |
| 법령 원문 | agc.gov.my (Attorney General's Chambers) |

**2차 출처(허용)**: KPMG / PwC / Deloitte / EY / BDO / Crowe / Grant Thornton + 로컬 회계법인 블로그 (Wolters Kluwer, ClearTax, jomeinvoice 등). 1차와 일치할 때만 사용.

## 6단계: bulk API 발행 (DB 직접 INSERT 절대 금지)

```json
  "content_tier": "tactical",
```

**주의**:
- `seo_description` 각 언어 모두 160자 이하

- `slug`는 언어별 현지어 기반
- 잘못된 사실 인용 금지 (4.5단계 검증 결과만 사용)

### 6.2 발행 실행

```bash
node /var/www/dev-backend/scripts/blog-bulk-publish.js /tmp/blog-<slug>.json
```

이 스크립트는:
1. `~/.purple-pos/creds.json` 또는 `PURPLE_USER`/`PURPLE_PASS` 로 SA 토큰 발급 (`POST /api/auth/login`)
2. `POST /api/contents/bulk` 로 발행

**금지된 우회 (Claude가 시도하면 안 되는 것)**:

- ❌ 권한 부족 시 별도 INSERT 스크립트 생성 — 자격증명 부재 메시지를 그대로 사용자에게 전달하고 멈춤

## 주의사항

- **0단계 (타깃 결정) 없이는 1단계 이후 진입 금지.** AskUserQuestion 으로 6 역할 + Auto 중 받기 전에 트렌드 리서치를 시작하지 않는다. 타깃이 정해진 다음에야 트렌드/고객DB/매트릭스가 한 줄로 정렬된다.
- **한 글 = 한 persona + 한 problem + 한 funnel**. 섞으면 메시지 흐려짐
- **PurpleHere 실재 기능만 언급** (DB AddonModule 목록 참조)
- 경쟁사 직접 비교 금지
- 광고처럼 읽히지 말고 **콘텐츠로** 읽히게 — 해결책 중심
- 숫자는 일반화된 추정치라도 "업계 평균" 맥락 명시
