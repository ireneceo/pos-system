## ★ 사용자 환경 / 권한 모델 (모든 단계 공통)

이 스킬은 **어떤 OS 사용자(irene/lua/...)가 실행해도 동일하게 작동**한다. 도메인 권한은 application-level RBAC(System Admin) 으로만 통과시킨다. **`.env` / `require('./models/...')` / `require('dotenv').config()` 같은 DB 직접 접근 패턴 절대 금지.**

이유: 백엔드는 `irene`으로 가동 중 → `.env`가 600. 다른 OS 사용자는 못 읽음. 이 스킬을 lua 세션에서 돌리면 그 패턴은 항상 실패한다.

**모든 admin 작업은 HTTP API 호출만 사용**한다 (login → 토큰 → admin endpoint).

### 자격증명 (자기 세션에서 한 번만)

```bash
node /var/www/dev-backend/scripts/setup-creds.js
```

→ SA username/password TTY 입력 → /api/auth/login 검증 통과 시 `~/.purple-pos/creds.json` 자동 작성 (chmod 600).
**틀린 자격증명은 거절되어 파일이 안 만들어진다** (디버깅 단순).

또는 `PURPLE_USER` / `PURPLE_PASS` 환경변수.

### 표준 헬퍼

| 스크립트 | 용도 |
|---|---|
| `node /var/www/dev-backend/scripts/setup-creds.js` | 자격증명 한 번 setup (TTY) |
| `node /var/www/dev-backend/scripts/sa-token.js` | SA JWT 한 줄 출력 (모든 admin curl/fetch 인증용) |
| `node /var/www/dev-backend/scripts/blog-bulk-publish.js <payload.json>` | bulk 발행 (login + bulk POST) |

자격증명이 없거나 SA가 아니면 명확히 에러 후 종료한다. 추측·우회 금지.

## 1.5단계: ★ 영상 트랙 결정 (카오스 vs 인터뷰)

> **사이클 패턴**: 운영 카오스 (Reel A) → 운영 카오스 (Reel B) → 현실 고백 인터뷰 (Reel C) → 반복. **카오스 2 : 인터뷰 1** 비율 (2주 1회 발행 기준).

직전 발행 2건의 영상 트랙을 조회 → 이번 트랙 자동 결정:

```bash
TOKEN=$(node /var/www/dev-backend/scripts/sa-token.js)
curl -s -H "Authorization: Bearer $TOKEN" \
  "http://localhost:3001/api/contents?type=blog&status=published&limit=3&sort=-published_at" \
  | python3 -c "
import json, sys
items = json.load(sys.stdin).get('data', {}).get('rows') or json.load(sys.stdin).get('data', [])
for it in items[:3]:
    title = it.get('translations', [{}])[0].get('title', '')
    # video_prompt 의 첫 줄에서 'Operational Chaos' 또는 'Confession Interview' 키워드
    vp = (it.get('translations', [{}])[0].get('video_prompt') or '')[:200]
    track = 'CHAOS' if 'Operational Chaos' in vp else ('INTERVIEW' if 'Confession Interview' in vp else 'unknown')
    print(f'  {track}: {title}')
"
```

→ 결과 해석:
- 직전 2건 모두 `CHAOS` → **이번은 INTERVIEW** (사이클 리듬 유지)
- 그 외 (CHAOS 1건 + INTERVIEW 1건, 또는 처음 발행) → **이번은 CHAOS**

이 결정을 4단계 주제 제안 표의 추천 트랙 컬럼에 반영. Irene 이 override 가능.

## 4.5단계: ★ 팩트 검증 (절대 생략 금지)

> **이 단계 없이 본문 생성으로 넘어가는 것은 금지된다.**
> 외부 LLM/검색 결과의 수치·날짜·법조항·세율은 모두 1차 출처로 교차 확인되어야 한다. 한 글에 잘못된 사실 1개가 들어가면 회사 신뢰가 깎이고, 마케팅 자산이 부채로 바뀐다.

### 검증 대상 (글에 인용될 모든 "사실")
- 정부 정책 / 법령 (LHDN, RMCD, MOF, BNM, KPDN, MITI, MOH 등)
- 시행일 / 마감일 / 유예기간 (Phase, deadline, grace period)
- 세율 / 임계값 / 면제 기준 (RM 금액, %, threshold)
- 벌금 / 처벌 조항 (Section 번호, RM 금액, 징역 기간)
- 통계 (시장 점유율, 거래량, 사용자 수)
- 제3자 가격 / 수수료 (DuitNow MDR, 카드사 fee)
- 경쟁사 기능 / 통계 — 직접 인용은 가급적 회피

### 1차 출처 우선순위 (반드시 .gov.my / .my 도메인을 먼저)
| 분야 | 1차 출처 |
|---|---|
| 세금 / e-Invoice | hasil.gov.my (LHDN 공식 FAQ + Implementation Timeline 페이지) |
| SST / 관세 | rmcd.gov.my, mysst.customs.gov.my (Service Tax Policy PDF) |
| 예산 / 정책 | mof.gov.my (Budget speech, press release) |
| 결제 / 은행 | bnm.gov.my, paynet.my (DuitNow QR 통계) |
| 노동 / 인력 | mohr.gov.my (EPF, SOCSO, 최저임금) |
| 식품 안전 / 할랄 | jakim.gov.my (할랄 인증), moh.gov.my |
| 통계 | dosm.gov.my (Department of Statistics Malaysia) |
| 법령 원문 | agc.gov.my (Attorney General's Chambers) |

**2차 출처(허용)**: KPMG / PwC / Deloitte / EY / BDO / Crowe / Grant Thornton + 로컬 회계법인 블로그 (Wolters Kluwer, ClearTax, jomeinvoice 등). 1차와 일치할 때만 사용.

**금지 출처**: 무명 블로그, AI 답변 캐시, Wikipedia (사실 인용 시), Reddit/Quora.

### 검증 절차 (Claude 자동 수행)
1. 본문에 인용될 사실을 **목록으로 추출** (날짜·금액·세율·조항 모두)
2. 각 항목에 대해:
   - 1차 출처 URL을 `WebFetch`로 직접 fetch (PDF 포함)
   - 1차 출처 접근 불가 시, **2개 이상의 2차 출처가 일치**하는지 `WebSearch`로 확인
   - 두 출처가 충돌하면 → Irene에게 보고하고 **더 보수적인 수치를 채택** (혹은 인용 자체를 빼기)
3. 검증 결과를 다음 표 형식으로 Irene에게 출력:

```
## 팩트 체크 결과 (인용 예정 항목)

| # | 주장 | 1차 출처 | 검증 결과 |
|---|------|----------|-----------|
| 1 | "Phase 4 RM1M-RM5M 2026-01-01 시행" | hasil.gov.my Implementation Timeline | ✓ 확인 |
| 2 | "RM10,000 거래 개별 e-invoice 의무" | hasil.gov.my FAQ + ClearTax 2026 guide | ✓ 일치 |
| 3 | "벌금 RM200-20,000/장, Section 120(1)(d)" | jomeinvoice 2026 update + ITA 1967 | ✓ 일치 |
| 4 | "푸드코트 SST 8% 2025-07-01" | RMCD STP 2/2025 | ✓ 확인 |
| 5 | "산업용 임대 6% 2026-01-01" | MOF press release 2025-07-01 | ⚠ 기존 주장 정정: 상업용/푸드코트는 8% 유지 |

(충돌 / 정정이 있는 경우 본문에 반영)
```

4. 정정이 발생하면 **이전 단계(주제 제안)에서 사용한 수치를 즉시 정정**해서 Irene에게 다시 보여주고 진행 동의 받기. 그래야 잘못된 후킹/제목으로 본문이 작성되지 않음.
5. 모든 항목 ✓ 확인 후 5단계(본문 생성) 진입. 충돌 미해결 항목이 있으면 **본문에서 그 사실 자체를 인용하지 않는다.**

### 자주 틀리는 함정 (PurpleHere 글에서 실제 발견된 패턴)
- ❌ "Phase X 일정"을 6개월/1년 단위로 잘못 외움 (자주 갱신됨)
- ❌ "Service Tax Y%"를 산업용/상업용 구분 없이 한 숫자로 단정 (실제는 분리됨)
- ❌ "벌금 RM N" 인용 시 Section 번호 틀림 (다른 법령의 조항을 가져옴)
- ❌ "Threshold RM Z" 면제/적용 방향 반대로 표기 (이하 면제 vs 이상 면제)
- ❌ "효력 발생일" — 발표일과 시행일을 혼동 (예: 2025-06 발표, 2025-07-01 시행)
- ❌ 경쟁사 가격을 인용해버림 (변경 빈번 + 비교 광고 위반 위험)

### 검증된 사실만 인용하고 — 검증 안 된 부분은 일반론으로 우회
1차 출처에 명시 안 된 추정치는 본문에서 **"업계 평균"** / **"보수적으로 추산"** 등 모호 표현으로 처리하거나 아예 빼기. 
"RM 12,000을 절약했다" 식의 단정형 수치는 PurpleHere 자체 데이터 없이 쓰면 안 됨.

## 5단계: 3언어 풀 콘텐츠 생성 (5단계 광고 구조)

`/블로그초안` 커맨드의 5단계 구조 + 후킹 7기법 + 다포맷 그대로 적용. **선택된 매트릭스 셀 + 영상 트랙을 인자로 전달**.

### 각 언어마다
- **블로그 본문** (800-1000 words, tactical 기준)
  - TL;DR 상단 박스
  - 5단계: 공감 → 문제 → 해결 → 증거 → CTA
  - H2 질문형 (AEO)
  - 외부 링크 2개 + 내부 링크 2개
  - Focus keyword 자연 반복
- **video_prompt** (15.0초, 9:16, CF 광고 퀄리티)
  - 트랙: 1.5단계에서 결정 (CHAOS / INTERVIEW)
  - 매트릭스 셀의 pain_point_line / chaos_visual / interview_truth 을 템플릿에 주입
  - 초별 정확한 콘티 (블로그초안 5-A 템플릿 그대로)
- **social_post** { title, body, hashtags[8-10] }
  - 영상과 동일 트랙 톤 (블로그초안 5-B 트랙 분기)
- **SEO/AEO 메타** (seo_title ≤70자, seo_description ≤160자, ai_summary, seo_keywords)

### 태그 자동 부여
- target_persona: 선택 주제에서 결정됨
- problem_category: 선택 주제에서 결정됨
- funnel_stage: 주로 MOFU (검토 단계)
- content_tier: tactical (주간 리듬)

### 다국어 현지화 (단순 번역 금지)
- **EN**: 비즈니스 / 팩트 / 국제적 / RM 화폐 / Sunway·Pavilion·KLCC

## 6단계: bulk API 발행 (DB 직접 INSERT 절대 금지)

위에서 만든 3언어 콘텐츠를 **bulk payload JSON 파일로 저장 → 표준 헬퍼로 발행**.

### 6.1 payload JSON 작성 (`/tmp/blog-<slug>.json`)

```json
{
  "type": "blog",
  "category_id": 6,
  "target_persona": "<persona>",
  "problem_category": "<problem>",
  "funnel_stage": "MOFU",
  "content_tier": "tactical",
  "status": "published",
  "translations": { "en": { ... }, "ms": { ... }, "zh": { ... } }
}
```

**주의**:
- `seo_description` 각 언어 모두 160자 이하
- `content`는 HTML 문법 정확 (longtext 제한 없음)
- `slug`는 언어별 현지어 기반
- 잘못된 사실 인용 금지 (4.5단계 검증 결과만 사용)

### 6.2 발행 실행

```bash
node /var/www/dev-backend/scripts/blog-bulk-publish.js /tmp/blog-<slug>.json
```

이 스크립트는:
1. `~/.purple-pos/creds.json` 또는 `PURPLE_USER`/`PURPLE_PASS` 로 SA 토큰 발급 (`POST /api/auth/login`)
2. `POST /api/contents/bulk` 로 발행
3. 결과 출력 — `translation_group_id` + 언어별 slug

**금지된 우회 (Claude가 시도하면 안 되는 것)**:
- ❌ `require('dotenv').config()` + `require('./models/Content')` 직접 INSERT
- ❌ "irene 사용자로 실행해주세요" 식의 핸드오프 — 이 스크립트는 lua 사용자도 그대로 실행 가능
- ❌ DB 직접 SQL (mysql CLI / sequelize-cli)
- ❌ 권한 부족 시 별도 INSERT 스크립트 생성 — 자격증명 부재 메시지를 그대로 사용자에게 전달하고 멈춤

자격증명 부재 / 잘못된 SA 비밀번호 / SA가 아닌 계정 → 스크립트가 명확히 실패 메시지 출력. **그 메시지를 그대로 사용자에게 전달하고 작업 종료**. 우회로 새 스크립트 만들거나 핸드오프 X.
