# /블로그리서치 — 주간 블로그 주제 리서치

**목적**: 다음 주(또는 다음 13개 슬롯) 발행할 블로그 주제 뱅크를 생성한다. 검색 수요 + 고객 대화 + 업계 뉴스 3축으로 교차 검증.

**호출**: `/블로그리서치` (인자 없음 — 자동으로 최신 컨텍스트 사용)

---

## ★ 사용자 환경 / 권한 모델

`require('dotenv')` / `require('./models/...')` 같은 DB 직접 접근은 **백엔드 운영 사용자(irene) 세션에서만 작동** (`.env` 권한 600). 다른 OS 사용자(lua 등)는 **HTTP API 호출**만 사용:

```bash
TOKEN=$(node /var/www/dev-backend/scripts/sa-token.js) || exit 1
curl -s -H "Authorization: Bearer $TOKEN" http://localhost:3001/api/contents
```

자격증명: `~/.purple-pos/creds.json` 또는 `PURPLE_USER`/`PURPLE_PASS`. 자격증명/권한 부족 → 우회 금지, 메시지 그대로 사용자에게 전달하고 종료.

## Claude가 수행할 작업

### 1단계: 고객 대화 추출 (내부 데이터)

dev-backend에서 최근 90일 고객 대화 집계:

```bash
cd /var/www/dev-backend && node -e "
const SupportTicket = require('./models/SupportTicket');
const ContactInquiry = require('./models/ContactInquiry');
const OperationTicket = require('./models/OperationTicket');
const { Op } = require('sequelize');
(async () => {
  const since = new Date(Date.now() - 90*24*60*60*1000);
  const tickets = await SupportTicket.findAll({ where: { created_at: { [Op.gte]: since } }, attributes: ['title','description','category'], limit: 100 });
  const inquiries = await ContactInquiry.findAll({ where: { created_at: { [Op.gte]: since } }, attributes: ['subject','message','inquiry_type'], limit: 100 });
  const ops = await OperationTicket.findAll({ where: { created_at: { [Op.gte]: since } }, attributes: ['title','description','category'], limit: 100 });
  console.log('Support tickets:', tickets.length);
  console.log('Contact inquiries:', inquiries.length);
  console.log('Operation tickets:', ops.length);
  // Output all raw text for Claude to analyze patterns
  [...tickets, ...inquiries, ...ops].forEach(t => console.log('---\\n' + (t.title||t.subject||'') + '\\n' + (t.description||t.message||'')));
  process.exit(0);
})();
" 2>&1 | tail -200
```

Claude: 출력에서 **반복되는 키워드/주제 5-7개** 추출. 특히 "how do I…", "can we…", "왜…안…되나요" 류 HOW/WHY 질문.

### 2단계: 업계 트렌드 (WebSearch)

아래 쿼리들을 WebSearch로 검색, 최신 3개월 이내 결과 요약:

- `"restaurant POS" malaysia 2026`
- `"food court" management trends Asia`
- `"franchise POS" challenges`
- `QR ordering regulation Malaysia Singapore`
- `restaurant technology AI 2026 trends`
- `food business startup Malaysia guide`

각 쿼리에서 **주제 후보 + 이벤트/규제/통계** 1-2개 추출.

### 3단계: 키워드 수요 평가 (WebSearch + 추정)

후보 주제마다 아래를 검색해서 상위 결과 Title/Description 분석:
- Google: `"[주제 키워드]"` (영어 / 말레이어 / 중국어)
- 결과 상위 10개에 **PurpleHere가 빠져있으면 기회**. 경쟁 블로그가 점유하고 있으면 차별화 전략 필요.

### 4단계: 주제 뱅크 13개 슬롯 제안

출력 형식 (표로):

### 5단계: 우선순위 + 발행 리듬 제안

```
주간 발행 캘린더 (권장):
  월: Tactical #1 (EN+MS+ZH 자동)
  화: Cluster #2 (EN+MS+ZH)
  수: Pillar #3 또는 Case Study (검수 필수)
  목: Tactical #4 (EN+MS+ZH 자동)
  금: News-jack #13 (관점 추가 필요)
```

### 6단계: 저장

결과를 `/var/www/docs/blog-research/YYYY-MM-DD-bank.md` 에 저장. 다음에 `/블로그초안`을 호출할 때 이 파일에서 주제 가져감.

## 주의사항

- 실제 결과를 Irene에게 **표 형식**으로 먼저 보여주고, 어떤 주제부터 착수할지 물어보기.
- 서비스 라우트가 이미 있는 기능(fc_floor_plan, brand_franchise 등)은 Tactical에 우선 배치 (PurpleHere 구독 전환으로 자연 연결 가능).
- "AI 시대" 류 너무 원론적 주제는 Pillar 1개에 몰아놓고 cluster에서 다루지 말 것.
