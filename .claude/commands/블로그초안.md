# /블로그초안 — 5단계 마케팅 구조 + 후킹 기반 3언어 블로그 작성

**목적**: 주제 1건을 받아 **광고 전환율 높은 5단계 구조** + **후킹 기법**으로 EN/MS/ZH 3언어 동시 생성. translation_group_id로 묶어 DB에 draft 저장.

**호출 예시**:
- `/블로그초안 topic="Peak hour POS freeze" persona=restaurant_owner funnel=MOFU tier=tactical`
- `/블로그초안 slot=2` (리서치 뱅크의 2번 슬롯)

---

## ★ 사용자 환경 / 권한 모델

`require('dotenv')` / `require('./models/...')` 같은 DB 직접 접근은 **백엔드 운영 사용자(irene) 세션에서만 작동** (`.env` 권한 600). 다른 OS 사용자(lua 등)는 **HTTP API 호출**만 사용:

```bash
TOKEN=$(node /var/www/dev-backend/scripts/sa-token.js) || exit 1
node /var/www/dev-backend/scripts/blog-bulk-publish.js /tmp/draft.json   # 발행
curl -s -H "Authorization: Bearer $TOKEN" http://localhost:3001/api/contents/categories  # read-only
```

자격증명: `~/.purple-pos/creds.json` 또는 `PURPLE_USER`/`PURPLE_PASS`. 자격증명/권한 부족 → 우회 금지, 메시지 그대로 사용자에게 전달하고 종료.

## 🎯 필수 5단계 구조 (반드시 지킬 것)

### 1. 공감 (Empathy) — 첫 1-2 문단
- 타겟이 **"내 이야기다"** 라고 느끼는 문장으로 시작
- 감정 / 상황 / 고민을 직접 건드림
- **절대 상품 설명으로 시작 금지**

예시 시작:
- ❌ "PurpleHere는 푸드코트 POS 시스템입니다" (상품 설명)
- ✅ "월요일 12시 30분. 점심 러쉬가 밀려오고 POS가 또 얼어붙었습니다." (공감)

### 2. 문제 (Problem) — 중간
- 왜 이 상황이 발생하는지 **구조적 원인** 짚기
- 단순 불만 아니라 **업계 공통 문제**로 프레임
- 독자가 "맞아, 이게 내 문제의 본질이었구나" 느끼게

예시:
- ❌ "POS가 느립니다" (단순 불만)
- ✅ "문제는 POS 성능이 아닙니다. 문제는 당신이 40개 매장의 20년 치 데이터를 단일 서버로 굴리고 있다는 것입니다." (구조적)

### 3. 해결 (Solution) — 3-5개 핵심만
- **"이걸 하면 된다"** 수준으로 직관적
- 간결한 숫자 리스트 (3-5개)
- 각 해결책마다 1-2문장이면 충분

### 4. 증거 (Evidence) — 신뢰 구축
- **숫자 / 사례 / 결과** 최소 1개
- "Sunway Pyramid에서는…" "500개 매장이 적용 후…" "X% 감소…"
- 없으면 **일반화된 사례**로 설득력 있게

### 5. 행동 (CTA) — 마지막 1 문단
- **지금 해야 하는 이유** 반드시 포함
- "나중에"가 아니라 **"지금"** 행동 유도
- 한 문장 강한 CTA + 구체 링크

## 🎣 후킹 기법 7가지 (제목 + 첫 줄에 녹여라)

### A. 손실 회피 (Loss Aversion)
사람은 이득보다 손실에 2배 강하게 반응.
- ✅ "월 RM 84,000이 새고 있습니다"
- ✅ "90%의 운영자가 놓치는 이것"

### B. 고정관념 깨기
당연하다고 믿던 것을 뒤집음. **반드시 사실 기반**.
- ✅ "Excel로 관리하는 게 답이 아닙니다. 원인은 다른 곳에 있습니다."

### C. 명확한 타겟 + 현실 공감
- ✅ "푸드코트 점주님들, 공실률 5%가 정말 괜찮을까요?"
- ✅ "프랜차이즈 3호점 준비 중이신가요?"

### D. 신뢰 선제공
- ✅ "500개 이상 F&B 매장이 사용하는"
- ✅ "20년차 푸드코트 운영자의 실전 노하우"

### E. 소외감 (나만 모르는 정보)
- ✅ "상위 10% 푸드코트만 쓰는 3가지 전략"
- ✅ "이걸 아는 사장님만 조용히 매출 2배"

### F. 70~80%만 주기 (체류시간 증가)
완전 다 안 주고 궁금하게. 마지막에 "더 자세한 건 데모에서" 같은.

### G. 심플/직관적 구조
- 숫자 리스트 (5가지 / 3가지)
- H2를 질문형 (AEO 유지)

인자: topic, persona, funnel, tier (default: tactical)


페르소나별 감정 앵커:
| 페르소나 | 공감 1문장 예시 |
|---------|----------------|
| restaurant_owner | "혼자 운영하는 매장이라면 이 장면이 익숙하실 겁니다." |
| brand_general | "3호점 오픈을 앞두고 밤잠 못 이루신 적 있나요?" |
| foodcourt_operator | "텅 빈 유닛을 지나칠 때마다 가슴이 답답하지 않으세요?" |
| owner | "여러 매장을 소유하면서 재무 리포트 맞추느라 주말을 쓰신 적 있나요?" |

### 2단계: EN 원본 — 5단계 구조대로 작성

**Tier별 분량**:
- tactical: 700-900 words (광고 효과 극대화 위해 짧게)
- cluster: 1200-1500 words
- pillar: 2000-2800 words

**분량 배분 (tactical 기준)**:
- 공감: 100-150 words
- 문제: 120-180 words
- 해결: 300-400 words (최대 비중)
- 증거: 80-120 words
- CTA: 60-100 words

**필수 포함 요소**:
- TL;DR 박스 (상단, 1-2문장, 손실/수치 강조)
- H2 질문형 (AEO 유지)
- 숫자 최소 3개 (구체성)
- 외부 링크 2개 (공식 출처 — DOSM, MIDA 등)
- 내부 링크 2개 (/features, /signup 또는 /pricing)
- "지금" 단어 CTA에 포함

### 3단계: MS 현지화

**단순 번역 금지**. 원칙:
- 감정/상황/예시는 **말레이 문화 기반**으로 교체
  - "lunch rush" → "waktu makan tengah hari" + "Ramadhan buka puasa rush"
  - RM 화폐 유지
  - 지명: Sunway, Pavilion, IOI, Mid Valley
- 톤: 친근/실용/공동체
- 할랄 관련 민감도 주의
- slug: Bahasa 기반

### 4단계: ZH 현지화 (Simplified)

- 감정/사례: 화교 비즈니스 컨텍스트
  - "午餐高峰" / "春节特殊营业时段"
  - 차이나타운, 호커센터, 화교 프랜차이즈 (Old Town White Coffee 등)
- 톤: 간결/효율/ROI 중심
- 4자성어 활용 가능 (如虎添翼 등)
- slug: pinyin 또는 영문 (중문 slug URL 깨짐)

### 5단계: 배포 키트 생성 (필수 — 블로그 글만 쓰고 끝내면 배포 못함)

각 언어마다 블로그 본문(content) 외에 **2가지 배포 자산**을 같이 생성:

**5-A. `video_prompt` (LONGTEXT)** — AI 영상 생성기(Sora / Runway / Veo / Pika)에 붙여넣을 **완전한 프롬프트**

필수 구성:
1. Format 명시: Vertical 9:16, 15-28s, subtitles always on
2. Scene breakdown (timestamp별): Hook → Problem → Solution → Evidence → CTA
   - 각 씬: Visual 설명 / Text overlay / Voice-over 대사 / Mood
3. **Thumbnail specification**: "First frame = thumbnail" 명시 + 텍스트 오버레이 문구 + 색상/폰트 크기
4. Visual style: 색상 팔레트, 조명, 카메라 컷, 타이포그래피, 음악 BPM, 자막 스타일
5. Voice-over full script (timestamps 제외한 낭독용)

템플릿 예시 (영어):
```
AI VIDEO PRODUCTION PROMPT
Format: Vertical 9:16 | Duration: 22-28s | Subtitles always on

═══════════════════════════════════════════════
SCENE BREAKDOWN
═══════════════════════════════════════════════

[0-3s] HOOK — First frame = thumbnail
  Visual: ...
  Text overlay (large bold, high contrast): "THUMBNAIL TEXT HERE"
  Voice-over: "..."
  Mood: ...

[3-10s] PROBLEM
  ...

[10-20s] SOLUTION
  ...

[20-24s] EVIDENCE
  ...

[24-28s] CTA
  ...

═══════════════════════════════════════════════
THUMBNAIL SPECIFICATION (First frame)
═══════════════════════════════════════════════
...

═══════════════════════════════════════════════
VISUAL STYLE
═══════════════════════════════════════════════
- Cinematic business-documentary
- Warm neutrals + PurpleHere #635BFF accents
- Typography: bold sans-serif (Inter/Poppins)
- Music: instrumental 80-100 BPM
- Subtitles: white + 70% black strip, 36-44px

═══════════════════════════════════════════════
SCRIPT (voice-over only, no timestamps)
═══════════════════════════════════════════════
{전체 낭독문}
```

**5-B. `social_post` (JSON)** — 모든 SNS 플랫폼 공통 1세트

```json
{
  "title": "포스트 제목 (Hook 역할)",
  "body": "멀티라인 본문 (문제→해결→증거→CTA, 끝에 [blog URL] 자리)",
  "hashtags": ["#tag1", "#tag2", ...]
}
```

주의:
- Twitter 안 씀. **페이스북/링크드인/스레드/유튜브/틱톡** 동일 텍스트 사용
- 해시태그는 8-10개 이내 (TikTok/Instagram 최적)
- 본문 끝에 `[blog URL]` placeholder (발행 시 실제 URL로 교체)

### 6단계: bulk API 호출

```javascript
POST /api/contents/bulk
{
  "type": "blog",
  "category_id": <id>,
  "target_persona": "<persona>",
  "problem_category": "<operations|customer_experience|data_decisions|management|organization|automation>",
  "funnel_stage": "<TOFU|MOFU|BOFU>",
  "content_tier": "<tier>",
  "status": "draft",
  "translations": {
    "en": {
      title, slug, content(HTML), excerpt,
      seo_title, seo_description<=160, seo_keywords, ai_summary,
      video_prompt,  // 5-A
      social_post    // 5-B { title, body, hashtags }
    },
    "ms": { ... },
    "zh": { ... }
  }
}
```

**중요**:
- seo_description은 **반드시 160자 이하** (VARCHAR(160) 제약)
- seo_title은 70자 이하
- content의 HTML은 큰 문자열이므로 임시 파일로 분리 권장 (`/tmp/blog-{lang}.html`)
- 인증: System Admin JWT 필요

### 6단계: 결과 보고 + 승인 대기

Irene에게:
- translation_group_id
- 3개 언어 draft URL (preview)
- 각 언어 TL;DR 3문장
- 훅(제목) 분석: 어떤 후킹 기법 적용했는지 명시

Irene 승인 후 `/블로그발행 <group_id>` 로 published 전환.

## 주의사항

- 한 글 = 한 페르소나 + 한 funnel. 섞으면 메시지 흐려짐.
- 해결 섹션에서 **PurpleHere 기능 언급은 증거 섹션과 연결** 자연스럽게.
- 경쟁사 이름 직접 공격 금지.
- 모든 숫자는 **일반화된 추정치**라도 "업계 평균" 등 맥락 명시.
- 광고처럼 보이지 않고 **콘텐츠처럼 읽히게** — 하드 세일 금지.
