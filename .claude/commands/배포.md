# 운영서버 안전 배포

운영서버에 안전하게 배포하는 명령어입니다.

---

## 배포 프로세스

### 1단계: 사전 확인

1. **Git 상태 확인** - 커밋 안된 변경사항 확인
2. **마지막 배포 이후 변경된 파일 확인** - `.last-deployed-commit` 파일로 이전 배포 커밋과 비교
3. **프론트엔드 빌드 테스트** - `npm run build` 실행하여 빌드 에러 없는지 확인

### 2단계: 변경사항 확인 및 커밋

배포될 변경사항 목록을 사용자에게 보여주고, 커밋 안된 것이 있으면 커밋합니다.

### 3단계: 배포 실행

배포 스크립트 실행:
```bash
/var/www/deploy-production.sh
```

**중요**: DB sync가 실패해도 프론트엔드 배포는 계속 진행됩니다.

### 4단계: 배포 검증 (자동)

배포 완료 후 반드시 다음을 확인합니다:

1. **배포된 커밋 확인**: `.last-deployed-commit` 파일의 커밋이 현재 HEAD와 일치하는지 확인
2. **프론트엔드 빌드 파일 확인**: `production-frontend/build/static/js/main.*.js` 파일의 타임스탬프가 방금 생성되었는지 확인
3. **PM2 서버 상태 확인**: `pm2 list | grep production`으로 서버가 online 상태인지 확인

### 5단계: 검증 실패 시 자동 재시도

만약 검증에서 다음 문제가 발견되면 자동으로 재배포를 시도합니다:

- 배포된 커밋과 현재 HEAD가 다름
- 프론트엔드 빌드 파일이 5분 이상 전에 생성됨
- PM2 서버가 online 상태가 아님

재시도 실패 시 사용자에게 알리고 수동 조치를 요청합니다.

## 필수 체크 항목

### 배포 전 반드시 확인:
- [ ] 마지막 배포 이후 변경된 파일 목록 확인
- [ ] 의도한 변경사항이 모두 포함되어 있는지 확인
- [ ] 프론트엔드 빌드 성공 확인
- [ ] 커밋 안된 변경사항 커밋 완료

### 배포 후 반드시 확인:
- [ ] `.last-deployed-commit`가 현재 HEAD와 일치
- [ ] `production-frontend/build/` 파일 타임스탬프가 최신
- [ ] PM2 production-backend가 online 상태
- [ ] https://purplehere.com 접속 정상
- [ ] 변경된 기능 동작 확인

---

## 검증 명령어 (수동 확인용)

```bash
# 1. 배포된 커밋 확인
cat /var/www/.last-deployed-commit
git rev-parse HEAD

# 2. 프론트엔드 빌드 시간 확인
ls -la /var/www/production-frontend/build/static/js/main.*.js

# 3. PM2 상태 확인
pm2 list | grep production

# 4. 백엔드 로그 확인
pm2 logs production-backend --lines 20
```

## 주의사항

- **DB sync 실패 시**: products.image 컬럼 이슈로 실패할 수 있음. 프론트엔드만 변경된 경우 수동으로 빌드/배포 진행
- **Settings 리셋 문제**: 배포 후 설정값이 바뀌면 원인 파악 필요
- **롤백**: `sudo /var/www/rollback-production.sh [타임스탬프]`

---

## 관련 파일
- `/var/www/DEPLOYMENT.md` - 상세 배포 가이드
- `/var/www/deploy-production.sh` - 배포 스크립트
- `/var/www/rollback-production.sh` - 롤백 스크립트
- `/var/www/.last-deployed-commit` - 마지막 배포 커밋 기록
