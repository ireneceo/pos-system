# 운영서버 배포 (원격 SSH)

개발서버(87.106.11.184)에서 운영서버(87.106.78.146)로 SSH 배포합니다.

---

## 배포 환경

| 서버 | IP | 역할 |
|------|-----|------|
| 개발서버 | 87.106.11.184 | dev-backend (3001), dev-frontend-build |
| **운영서버** | **87.106.78.146** | production-backend (3002), production-frontend |

**중요**: 운영 코드는 원격 서버(87.106.78.146)에만 존재합니다. 개발서버에는 production-backend/frontend 디렉토리가 없습니다.

---

## 배포 스크립트

**사용할 스크립트: `/var/www/deploy-to-production.sh`**

### 배포 단계

| 단계 | 작업 |
|------|------|
| 1 | SSH 연결 확인 (87.106.78.146) |
| 2 | 개발서버 헬스체크 (localhost:3001) |
| 3 | 운영서버 백업 생성 |
| 4 | 프론트엔드 로컬 빌드 (npm run build:dev) |
| 5 | rsync: dev-backend → 운영서버 production-backend |
| 6 | rsync: dev-frontend/build → 운영서버 production-frontend/build |
| 7 | 운영서버 npm install --production |
| 8 | PM2 production-backend 재시작 |
| 9 | 운영서버 헬스체크 (localhost:3002) |
| 10 | Nginx 리로드 |

## 배포 완료 후 CHANGELOG 업데이트 + 버전 업데이트 + 릴리즈 노트 출력 + 블로그 포스트 자동 생성

### CHANGELOG.md 업데이트 (필수)

배포 성공 시 `/var/www/CHANGELOG.md`의 `[Unreleased]` 섹션 내용을 새 버전 섹션으로 이동:

1. `[Unreleased]` 아래 내용을 모두 복사
2. `[Unreleased]` 아래를 비우고 (섹션 헤더는 유지)
3. 바로 아래에 새 버전 섹션 생성: `## [vX.XX] — YYYY-MM-DD 배포`
4. 복사한 내용을 날짜 헤더 없이 (flat list로) 새 버전 아래에 붙여넣기
5. 릴리즈 노트 작성 시 이 내용을 그대로 참고

### 버전 업데이트 (Irene에게 확인)

배포가 성공하면 **Irene에게 버전을 올릴지 물어본다.**

질문: "버전 올릴까요? (현재 v3.4)"

- **올린다고 하면**: patch 버전 +1 → session-state.md, DEVELOPMENT_PLAN.md, CHANGELOG.md 반영 + 릴리즈 노트 출력
- **안 올린다고 하면**: 버전 유지, 릴리즈 노트 생략

버전은 **배포 시에만** 올린다. `/개발완료`에서는 버전을 변경하지 않는다.

### 릴리즈 노트 출력

**배포가 성공적으로 완료되면, 마지막에 반드시 왓츠앱용 릴리즈 노트를 생성하여 출력합니다.**

#### 작성 규칙
1. 이번 배포에 포함된 주요 변경사항을 **CHANGELOG.md의 새 버전 섹션**에서 수집 (1차 소스)
2. 추가로 DEVELOPMENT_PLAN.md와 git diff도 참고하여 누락 없는지 확인
3. 한글 + 영문 둘 다 작성
4. 왓츠앱에서 깔끔하게 보이도록 마크다운 리스트(-, *) 사용 금지
5. 이모지 넘버(1️⃣ 2️⃣ 3️⃣ 4️⃣)와 줄바꿈으로 구조화
6. 구분선은 `━━━━━━━━━━━━━━━━━━` 사용
7. **제목 형식: `📢 PurpleHere POS Update v{버전}`** (한글 제목 사용 금지)

#### 출력 형식 예시

```
📢 PurpleHere POS Update v3.5
YYYY년 M월 D일

━━━━━━━━━━━━━━━━━━

1️⃣ [기능명]

[설명 한 줄]
[설명 한 줄]

2️⃣ [기능명]

[설명 한 줄]
[설명 한 줄]

━━━━━━━━━━━━━━━━━━

📢 PurpleHere POS Update v3.5
Month DD, YYYY

━━━━━━━━━━━━━━━━━━

1️⃣ [Feature Name]

[Description line]
[Description line]

━━━━━━━━━━━━━━━━━━
```

### 릴리즈 콘텐츠 자동 등록 (랜딩 블로그 + System Admin 공지)

**버전을 올렸으면 반드시 실행.** 버전 미변경 시 생략.

배포가 성공하고 릴리즈 노트를 작성했다면, 같은 내용을 **두 곳에 동시 자동 등록**합니다:
1. **랜딩 페이지 블로그** — 영어 1개 포스트 (`updates` 카테고리)
2. **System Admin 공지** — 영어 + 한글 이중언어 공지 (`updates` 카테고리, target_type=all)

#### 실행 방법

1. 릴리즈 JSON 생성 — 랜딩은 영어, 공지는 영어/한글 동시 포함:

```json
{
  "version": "3.13",
  "date": "YYYY-MM-DD",
  "landing": {
    "title": "PurpleHere POS v3.13 Update",
    "content": "## What's New\n\n- Feature one: user-facing description\n- Feature two: ..."
  },
  "notice": {
    "title": "PurpleHere POS Update v3.13",
    "content_en": "1️⃣ Feature A\n\nDescription line\nSecond line\n\n2️⃣ Feature B\n\n...",
    "content_ko": "1️⃣ 기능 A\n\n설명 한 줄\n두 번째 줄\n\n2️⃣ 기능 B\n\n..."
  }
}
```

2. 스크립트 실행 (dev DB 생성 + 운영 DB 자동 동기화):
```bash
cat /tmp/release-v3.13.json | node /var/www/dev-backend/scripts/create-release-post.js --stdin --sync-prod
```

- `--stdin`: JSON을 stdin에서 읽음
- `--sync-prod`: SSH로 운영 DB 자동 동기화 (블로그 포스트 + 공지 + 수신자 생성 포함)

3. 결과 확인:
- 랜딩 블로그: `https://purplehere.com/blog?category=updates`
- System Admin 공지: 모든 역할의 공지 페이지에 노출됨 (target_type=all)

#### 콘텐츠 작성 가이드라인

**랜딩 블로그 (영어 단일):**
- 제목 형식: `PurpleHere POS v{version} Update`
- 내용: 사용자 친화적 영문. 마크다운 `##` 섹션 + `-` 리스트 사용 가능
- **기술 세부사항 제외**: 파일 경로, 함수명, 내부 변수 금지. 사용자가 체감하는 화면/기능 위주
- 고유명사 유지: PurpleHere, POS, QR 등 영문 그대로

**System Admin 공지 (이중언어):**
- 제목 형식: `PurpleHere POS Update v{version}` (영어)
- content_en / content_ko 각각 이모지 번호(1️⃣ 2️⃣ 3️⃣)와 줄바꿈으로 구조화
- 마크다운 리스트(`-`, `*`) 사용 금지 — WhatsApp 스타일 프리텍스트
- 스크립트가 자동으로 `content_en` + `━━━━━━━━━━━━━━━━━━` + `content_ko`로 결합하여 하나의 공지 content에 저장
- 기존 v3.12 공지 포맷 그대로 따름

#### 스크립트 동작 상세

- `updates` 카테고리는 최초 1회만 생성 (blog: `ContentCategory`, 공지: Notice.category ENUM)
- 블로그 slug 패턴: `release-v{version}` (예: `release-v3.13`)
- 재실행 시 동일 version이면 업데이트 (중복 생성 안 됨)
- 공지 수신자는 is_demo=false/is_test=false 인 모든 레스토랑 + 4개 역할(Admin/Brand/Foodcourt/Owner) 사용자 자동 생성
