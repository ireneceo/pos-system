# 운영서버 배포 (원격 SSH)

개발서버(87.106.11.184)에서 운영서버(87.106.78.146)로 SSH 배포합니다.

---

## 배포 환경

| 서버 | IP | 역할 |
|------|-----|------|
| 개발서버 | 87.106.11.184 | dev-backend (3001), dev-frontend-build |
| **운영서버** | **87.106.78.146** | production-backend (3002), production-frontend |

**중요**: 운영 코드는 원격 서버(87.106.78.146)에만 존재합니다. 개발서버에는 production-backend/frontend 디렉토리가 없습니다.

---

## 배포 스크립트

**사용할 스크립트: `/var/www/deploy-to-production.sh`**

### 배포 단계

| 단계 | 작업 |
|------|------|
| 1 | SSH 연결 확인 (87.106.78.146) |
| 2 | 개발서버 헬스체크 (localhost:3001) |
| 3 | 운영서버 백업 생성 |
| 4 | 프론트엔드 로컬 빌드 (npm run build:dev) |
| 5 | rsync: dev-backend → 운영서버 production-backend |
| 6 | rsync: dev-frontend/build → 운영서버 production-frontend/build |
| 7 | 운영서버 npm install --production |
| 8 | PM2 production-backend 재시작 |
| 9 | 운영서버 헬스체크 (localhost:3002) |
| 10 | Nginx 리로드 |

## 배포 완료 후 버전 업데이트 + 릴리즈 노트 출력

### 버전 업데이트 (Irene에게 확인)

배포가 성공하면 **Irene에게 버전을 올릴지 물어본다.**

질문: "버전 올릴까요? (현재 v3.4)"

- **올린다고 하면**: patch 버전 +1 → session-state.md, DEVELOPMENT_PLAN.md 반영 + 릴리즈 노트 출력
- **안 올린다고 하면**: 버전 유지, 릴리즈 노트 생략

버전은 **배포 시에만** 올린다. `/개발완료`에서는 버전을 변경하지 않는다.

### 릴리즈 노트 출력

**배포가 성공적으로 완료되면, 마지막에 반드시 왓츠앱용 릴리즈 노트를 생성하여 출력합니다.**

#### 작성 규칙
1. 이번 배포에 포함된 주요 변경사항을 DEVELOPMENT_PLAN.md와 git diff에서 수집
2. **이전 배포 이후 미공지된 변경사항도 모두 포함** (session-state, DEVELOPMENT_PLAN 히스토리 확인)
3. 한글 + 영문 둘 다 작성
4. 왓츠앱에서 깔끔하게 보이도록 마크다운 리스트(-, *) 사용 금지
5. 이모지 넘버(1️⃣ 2️⃣ 3️⃣ 4️⃣)와 줄바꿈으로 구조화
6. 구분선은 `━━━━━━━━━━━━━━━━━━` 사용
7. **제목 형식: `📢 PurpleHere POS Update v{버전}`** (한글 제목 사용 금지)

#### 출력 형식 예시

```
📢 PurpleHere POS Update v3.5
YYYY년 M월 D일

━━━━━━━━━━━━━━━━━━

1️⃣ [기능명]

[설명 한 줄]
[설명 한 줄]

2️⃣ [기능명]

[설명 한 줄]
[설명 한 줄]

━━━━━━━━━━━━━━━━━━

📢 PurpleHere POS Update v3.5
Month DD, YYYY

━━━━━━━━━━━━━━━━━━

1️⃣ [Feature Name]

[Description line]
[Description line]

━━━━━━━━━━━━━━━━━━
```
