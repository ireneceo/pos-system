# 운영검증 — 배포가 못 잡는 것을 운영서버에서 철저히 검증

> **언제:** `/배포` 직후, 또는 운영 이상 신고 시. 배포 게이트(build/health/state-hydration)는 **정적·DEV 기준**이라 못 잡는 것 — 실프린터 종이 출력, 실 하드웨어(QZ Tray/RawBT), 매장별 실제 설정 분기, 운영 전용 데이터 — 을 **운영서버에서** 직접 증명한다.
>
> **`/검증`(DEV) 와 다른 점:** `/검증` 은 dev-backend(3001) 대상. `/운영검증` 은 **운영서버(87.106.78.146, 3002)** 대상 + 실프린터 눈 확인 체크리스트 포함.

---

## 🛡️ 절대 안전 원칙 (위반 시 즉시 중단)

1. **운영 클론 매장만 write.** 신규 주문/결제/재고 생성·수정은 **반드시** `is_test=true` + 이름 `[TEST] *` + 이메일 `@test.invalid` 인 클론 매장에서만. 실고객 매장(The Fire 등) 은 **GET 조회만**.
2. **실 게이트웨이 과금 금지.** 결제는 기록방식(counter/card/ewallet) 또는 sandbox(Stripe test/PayPal sandbox)만. 운영 webhook URL 호출 금지.
3. **운영 코드/설정/스키마 수정 금지.** 이 스킬은 **검증 전용**. 버그 발견 시 → DEV 에서 고쳐 `/배포` 로만 반영.
4. **정리 의무.** 클론 매장은 검증 후 **FK 까지 완전삭제**(orders/items/payments/floor_plan 등) + 잔여 0 확인. 메일 발송 3중 차단(`.invalid`/`unverified`/`is_test`) 전제.
5. **민감정보 미로깅** — 토큰/비밀번호 출력 금지.

## 실행 단계

### 1. 연결 + 운영 health
```bash
ssh irene@87.106.78.146 "curl -s --max-time 5 http://localhost:3002/api/health"
# "status":"ok" + uptime 확인
```

### 2. 운영 smoke (역할별 핵심 API — 조회 위주, 실매장 안전)
- 배포 스크립트 §14 smoke 와 동일 패턴: SSH → `curl localhost:3002` → 로그인 → 역할별 핵심 GET.
- Admin / Brand / Foodcourt / Owner / Restaurant 각 로그인 + dashboard·orders·menu·invoices 200 확인.
- 익명 401, 타매장 IDOR 차단 등 보안 게이트는 운영에서도 통과해야 함.

### 3. 운영 클론 매장으로 전 주문루트 (결제완료까지)
- 검증 대상 실매장과 **동일 설정** 클론 생성(`[TEST] <원본> Clone`, is_test, @test.invalid). printer_settings/payment_settings/table_settings/floor_plan 복제.
- `docs/PRINT_RULES_MATRIX.md` 의 **주문루트 표 전체**를 운영서버에서 실호출:
  - POS 직접 / Floor Plan 오버레이 / 모바일(테이블QR·공용슬러그) / takeaway / +Round / **테이블 이동(빈·머지)** / **아이템 취소** / **주문 전체 취소** / 결제 빌.
  - 각 루트 → 주문 생성 → (해당 시) station 분배·머지·이동·취소 → 결제완료까지 API 응답으로 데이터 흐름 증명.
- **매트릭스 대조**: 각 셀의 "어떤 티켓이 / 어느 프린터에 / 몇 장 / 어떤 헤더" 중 **API/백엔드에서 검증 가능한 부분**(pending-print 큐, printed_at, station_id, removedItem payload, noticeHeader 플래그)을 표와 1:1 대조.

### 4. 🖨️ 실프린터 눈 확인 체크리스트 (Irene 수행 — 코드/headless 불가)
> 종이 출력은 사람 눈으로만 검증 가능. 아래를 운영 실매장(또는 매장 동의된 클론 단말)에서 확인.

- [ ] **신규 주문**: station 별 오더티켓 정확히 1장씩 (중복 0). POS 미러 ON 매장은 빌프린터에 통합 1장 추가.
- [ ] **+Round 추가주문**: 추가 품목만 `** ADDITIONAL ORDER **` 1장 (이전 품목 재발행 0).
- [ ] **테이블 이동(빈)**: 옛 station VOID 1장 + 새 station 재발행 1장, 헤더 `** TABLE CHANGED **`.
- [ ] **테이블 이동(머지)**: 헤더 `** TABLE CHANGED + MERGED **` + "이전 N장 버리라" 문구.
- [ ] **아이템 취소**: 해당 station 에 `*** ITEM CANCELLED ***` + 취소 아이템 줄긋기 + 사유.
- [ ] **주문 전체 취소**: station 별 `*** ORDER CANCELLED ***` + 전 아이템 줄긋기.
- [ ] **자동발행 OFF 매장**: 위 액션이 **자동으로 안 나옴** → 액션 모달의 "확인+인쇄" 로만 발행.
- [ ] **한글·디자인**: QZ Tray HTML pixel 경로 한글 정상(깨짐 0).
- [ ] **Issue 1**: Floor Plan 오버레이로 테이블 POS 열고 주문 → 키친 티켓 **정확히 1장**(2장 중복 재발 0).

### 5. 매장별 주요설정 분기 확인
- 운영 DB 의 **진짜** printer_settings 로: autoPrint master ON/OFF, station 유무, printPerItem, mirrorToBill, printCancellationTicket, billPrinter.autoPrint, printerMode(rawbt/browser/qz), 멀티존 — 매장마다 다름. 대표 매장 2~3곳 설정을 매트릭스와 대조.

### 6. 정리
```bash
# 클론 매장 FK까지 완전삭제 후 잔여 0 확인 (orders/items/payments/floor_plan/...)
```
