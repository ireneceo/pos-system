## 0. 판단 요지

1. **«반응형이 이상하다»의 정체는 넘침이 아니라 배치 품질이다.** 기계 측정은 넘침·화면 밖 버튼만 잡아서 «거의 문제없음»으로 나왔지만, 사진에는 분명히 이상한 것이 보인다. 지금 측정기는 이것들을 못 잡는다 → **측정기부터 보강한다**(§4). 내가 사진에서 직접 확인한 것:
   - 탭이 폰에서 2~3줄로 접히고 밑줄이 어긋남 (FG 인보이스 375, RA 문의 375, live-orders 375)
   - 표가 카드로 바뀔 때 **가운데 정렬과 왼쪽 정렬이 한 카드 안에 섞임** (admin 직원 768, FG 구독 768)
   - 통계 카드 3개가 2+1 로 떨어져 빈 구멍 (admin 직원 768) · 1024 에서 2×2 큰 카드가 첫 화면을 다 차지 (인보이스 1024)
   - 필터 줄이 들쭉날쭉 — 폭이 제각각, 줄 절반만 채움 (FG 구독 768, live-orders 375·768)
   - 카드 내용이 화면 오른쪽에서 잘림: RA 시스템 문의 375 의 «CLOSE…»·«HIG…» 꼬리표 (누르는 요소가 아니라서 측정기가 놓침)
   - 빈 상태가 작은 상자로 왼쪽에 붙음 (reservations «No reservations»)
   - 제목이 좁은 칸에서 3줄로 쪼개짐 (RA 대시보드 375 «Sales & Orders Overview»)
   - 번역 키 오류 문구가 화면에 그대로: 발주 화면 «key 'newPo.brandStock (en)' returned an object instead of string.»
2. **«같은 기능인데 다른 화면»의 뿌리는 부품 묶음이 갈라진 것**(버튼 4벌·머리 2벌·탭 2벌·표 2벌)과 **역할별 복사본**이다. 순서는 **공용 부품 먼저 → 가족별 맞추기 → 화면별 잔여**. 공용 부품 하나를 고치면 수십 화면이 같이 낫는다.
3. **화면 파일을 합치는 일(코드 중복 제거)은 이 일의 목표가 아니다.** 목표는 «사용자 눈에 같은 기능은 같은 모양·같은 순서». 페이지 합치기는 하지 않고, **글자까지 같은 로컬 표현 부품(카드·격자)만 공용으로 뽑는다**(§3-C).
4. **기준은 RA.** 실측한 RA 순서: **머리(제목+행동) → 통계 카드 → 탭 → 필터 → 목록 → 쪽 나눔** (RA Invoices·Support·Notices·Staff 4화면 모두 이 순서).

### 3단계 — 가족별 (C1 → C12 순서)
가족 하나 = 되돌릴 수 있는 한 묶음(따로 저장). 가족 3~4개마다 묶어 빌드해 사진으로 확인해도 된다(빌드 ②③ — **빌드는 전체 통틀어 5회 이하**, mount sweep 은 맨 끝 1회).
가족마다: 기준 화면 실측(grep) → 대조표(무엇을 맞추고 무엇은 왜 다르게 두는지) → 편집 → 그 가족 화면만 재측정·대조판(후).

### 5단계 — 마감

### 일하는 규칙
- 🔒 `check-print-guard` 를 **묶음마다** 돌린다(초 단위). 지문이 뜨면 즉시 사본으로 되돌림(`git checkout`·`reset --hard` 금지).
- 문구를 바꾸면 4개 언어 전부 + `i18n:verify`.
- **이 설계와 다른 판단이 필요해지면**(공용 부품을 보호 화면이 쓰고 있어 길이 막힘 / 맞추려면 서버·결제 동작을 바꿔야 함 / 기준 화면끼리 서로 다름) 그 항목은 **멈추고 «보류 — 이유»로 기록**, 나머지를 계속한다. 보류 목록은 마감 검증 때 한 번에 판정.

**없음.** 전부 개발서버의 화면 코드 변경이고 묶음 단위로 되돌릴 수 있다. 아래는 내가 정했고 묻지 않는다(되돌릴 수 있음):

**알려 둘 것(질문 아님):** 인보이스 결제 방식이 역할마다 다른 것(RA 호스팅 결제창 / Owner·FG 카드 폼 / BG 카드+PayPal)은 이번에 손대지 않는다. 화면 모양은 같아지지만 «Pay» 를 누른 뒤의 흐름은 역할마다 그대로 다르다. 이것까지 맞추려면 돈이 걸린 별도 일(설계 + 게이트)이다.
