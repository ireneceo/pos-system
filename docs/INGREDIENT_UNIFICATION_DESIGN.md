## 1. 확정 모델

### 여섯 줄
1. **Stock Item = 유일한 재료 목록**(소유자 기준). 공급처 연결(공급업체 상품 또는 GIT 프로덕트, 환산비 포함)은 여기 붙는다.
2. **브랜드 프로덕트 = 파는 것.** 가격이 사는 곳이다. **재료 행을 만들지 않는다.**
3. **매장 재료 행 = Stock Item 의 거울**(브랜드별, 기계가 유지). 사람은 못 고친다.
4. 레시피는 Stock Item 을 고르고, 매장에서는 거울로 해석된다. **재고 차감·인쇄 상품 해석 코드는 무접촉.**
5. **출처는 둘 중 하나다** (2026-09-04 추가):
   GIT 이 **사서 쓰는 것**(원재료·소모품) → 출처 = **Stock Item**.
   GIT 이 **파는 것**(프로덕트: K-소스 완제품·포장재·굿즈) → 출처 = **브랜드 프로덕트**. Stock Item 을 만들지 않는다.
   > 근거: 2026-09-01 `migrate-git-merge-packaging` 결정 — "레시피 없는 프로덕트는 그 자체가 재고아이템"(수량이 프로덕트에 산다).
   > 파는 물건에 Stock Item 을 또 만들면 그때 합쳐 놓은 것이 **다시 갈라진다.**
   > 실측(2026-09-04): 활성 브랜드 재료 143건 중 **86건**이 소유 브랜드의 활성 프로덕트와 같은 물건이었다
   > (명시 연결 25 + 전 브랜드 배포 61). 이 규칙이 없었으면 86건이 또 두 줄이 됐다.
   열쇠 = `ingredients.source_brand_product_id`. **둘 다 채워진 행은 결함**(ING-UNI-004 가 잡는다).
6. **단위 규칙**: Stock Item 의 단위 = **우리가 쓰는 단위**(g·ml). **공급업체 포장(14kg·1kg·18L)은 재료가 아니라 그 재료의 공급처 연결에 붙는 환산비다.**
   > Irene 원문: "당면 14kg는 공급업체 판매 기준이야. 이게 재료이고. 그런데 우리는 단위 낮춰서 재료로 쓰는 거지."

### 왜 테이블을 물리적으로 합치지 않는가
매장 재료 테이블(`ingredients`)에 **재고 차감 · 레시피 · 발주 · 매장 덧씌우기**가 전부 물려 있다.
운영 실측 기준 레시피 줄 302 · 덧씌우기 137 · 원장 57 · 발주 연결 10 이 이 테이블을 가리키고 있고,
테이블을 옮기면 그 배선을 전부 다시 깔아야 한다. 거울이 사용자에게 안 보이면 "목록이 하나"라는
목적은 달성되므로 **물리 통합은 비목표**로 둔다.

> **정정 (2026-09-04):** 이 문서 초판에 "인쇄 상품 해석(`resolveProductId`)이 물려 있어 옮기면
> 🔒 인쇄 보호 영역까지 닿는다"고 썼는데 **과장이었다.** 실측하면 인쇄 보호파일 8개 중
> `billPrint` · `useAutoPrintPoller` · `KitchenDisplayPage` · `POSTerminalPage` · `stationEnrichment` ·
> `orderTotals` 는 `ingredient` 를 **한 번도 언급하지 않고**, `orders-crud.js` 는 차감 **결과 로그 한 줄**,
> `MainLayout.tsx` 는 **사이드바 메뉴 링크**뿐이다. `resolveProductId` 가 해석하는 것은 **메뉴·상품**이지
> 재료가 아니다. 인쇄는 재료를 읽지 않는다. 물리 통합을 미루는 이유는 위 배선 하나뿐이다.

### 합치기 원칙 (Irene 지시)
**있으면 붙이고, 없을 때만 옮긴다. 새 행을 추가해 두 줄이 되는 결과는 금지.**

### 이름 정본 규칙 (Irene 지시: "긴이름으로 다 써")
**레시피가 붙어 있는 행을 그대로 남기고, 이름만 GIT 프로덕트의 긴 이름으로 바꾼다.**
예: `K-Gochujang` → `K-Gochujang Sauce 1kg`. Stock Item 이름도 같은 긴 이름으로 통일.
- **레시피 줄 302개는 한 줄도 움직이지 않는다. 단위(g)도 그대로.** 이름표만 바꾸는 것이라 위험이 없다.
- **적용 범위 = GIT 프로덕트가 있는 것만.** 매장이 현지에서 사는 원재료(콩나물·달걀·마늘 등)는 이름을 유지한다.
- GIT 프로덕트 이름의 철자를 그대로 따른다(예: `Glass Noddle 1kg` — 철자 수정은 Irene 몫, 우리가 고치지 않는다).

## 2. 기능 정의

| # | 기능 | 내용 |
|---|---|---|
| F1 | Stock Item 공유 | Stock Item 폼에 "매장 공유: [with MIN] [K-DINE]" 체크. 켜면 그 브랜드에 거울 생성, 끄면 거울 비활성(참조가 있으면 끌 수 없음 — 카테고리 삭제와 같은 규칙) |
| F2 | 거울 자동 유지 | Stock Item 의 이름·단위·카테고리·활성 변경이 거울에 따라간다. **방향은 Stock Item → 거울 한 방향뿐** |
| F3 | 거울 보호 | 거울 행의 **이름·단위·카테고리** 직접 수정 API → **403**("Stock Items 에서 수정하세요"). **매장 재고·최소치 입력은 그대로 열려 있다** — 403 은 거울 행 자체만 잠근다 |
| F4 | 레시피 재료 선택 | 브랜드 레시피 재료 선택기가 **Stock Items** 목록을 보여준다. 저장 시 그 레시피 브랜드의 거울로 해석(거울이 없으면 공유를 자동으로 켜고 생성) |
| F5 | 프로덕트 복제 폐기 | `syncProductToIngredients` 진입부에서 **즉시 반환**. 프로덕트는 재료 행을 낳지 않는다 |
| F6 | 화면 정리 | 사이드바 Shared Ingredients 제거, 라우트는 Stock Items 로 리다이렉트. 매장 화면은 **무변경**(거울을 그대로 봄) |
| F7 | "매장에 실제로 얼마나 있나" 표시 살리기 | Stock Items 목록의 `linked_stock` / `linked_store_total` / `linked_stores` 를 새 열쇠(§3-1)로 역조회한다. 지금은 열쇠가 0건이라 **항상 null**. 담기 화면의 중복 판정(`already_linked`)도 같은 열쇠로 — 안 바꾸면 통합 후에도 중복을 못 막는다 |

## 3. DB

### 3-1. 스키마 변경 — 거울 열쇠 신설
**`ingredients.source_product_ingredient_id`** (INTEGER, nullable, 인덱스) 신설.
- 방향: **거울 N → Stock Item 1.** 한 Stock Item 이 브랜드 둘에 공유되면 거울이 둘이므로, 열쇠는 거울 쪽에 있어야 한다.
- "공유 여부"는 별도 플래그 없이 **활성 거울의 존재**로 정의한다.
- 동기화는 Stock Item → (이 열쇠로 조회한) 거울들.

**`product_ingredients.linked_ingredient_id` 는 쓰지 않는다.** Stock Item 1 → 거울 1 밖에 못 담아 F1 과 모순이고, 코드 주석이 쓰기를 금지한다. 폐기 표시만 하고 데이터는 0건 그대로 둔다. 이 컬럼을 읽는 3곳(`routes/product-ingredients.js` 표시용 · `routes/stock-ledger.js` 중복판정 · 모델 정의)은 **F7 에서 새 열쇠로 바꾼다**.

### 3-2. 마이그레이션 순서 (각 단계 드라이런 → 증명 → 롤백 가능, 레지스트리 `manual`)

**① 프로덕트 복제 경로 끄기** — 새 거울이 더 생기지 않게 먼저 잠근다.
> ⚠ `syncProductToIngredients` 는 `sync_to_ingredients=false` 이면 **기존 연결 재료를 제거한다**(`routes/brand-products.js:56~57`). "끈다"가 그 제거를 타면 **매장 8 덧씌우기가 날아간다.**
> 반드시 **진입부에서 즉시 반환**(제거 로직 포함 아무것도 실행하지 않음) — 인쇄 하이브리드 비활성과 같은 방식.

**② 210건 대응**

| 구분 | 건수 | 처리 |
|---|---|---|
| 이름 완전일치 | 126 | 기존 Stock Item 에 **붙임**(열쇠 설정). 새로 만들지 않음 |
| 영문 본체만 일치 | 19 | 후보가 정확히 1개일 때만 붙임 |
| 후보 2개 이상 | 2 | ⑦ 에서 Stock Items 를 먼저 정리하면 후보가 하나로 줄어든다 |
| 대응 없음 | 63 | Stock Item 생성 후 붙임 — **이동이지 중복이 아니다** |

**63건의 두 부류** (문서에 명시해 "왜 콩나물이 GIT 재고에?" 를 미리 막는다):
- **K-소스 완제품 12건** → Stock Item 신설 = **GIT 완제품 재고**(단위 g, 긴 이름). 이름 바꾼 브랜드 행이 그 거울. "GIT 이 만든 것도 GIT 재고" 라는 §1-1 의 귀결이다.
- **매장이 현지에서 사는 원재료**(Bean Sprout · Egg · Garlic Peeled · Filter water 등) → Stock Item 신설, **GIT 재고 0**.
  > 목록은 브랜드가 정의한 재료 전체이고, 재고 수량은 주인별이다. **GIT 이 취급하지 않는 재료가 GIT Stock Items 에 재고 0 으로 있는 것이 정상.**

카테고리는 이름으로 표준 세트에 대응, 없으면 `Other`.

**③ K-소스 이름 두 벌 정리** — 한 재료의 두 얼굴이지 두 재료가 아니다.
- **남길 것: 레시피가 붙어 있는 행**(현재 짧은 이름, 단위 g).
- 그 행의 **이름을 긴 이름으로** 바꾼다. **레시피 줄·단위 무이동.**
- 긴 이름을 달고 있던 옛 거울 행(레시피 0): 덧씌우기 1건씩을 남는 행으로 옮기고(매장 8 K-* 재고가 전부 0 이라 실질 0) **비활성**(삭제 아님).
- 공급처 연결은 남는 행에 붙이고 **환산 1 pack = 1000 g**. 사면 1 pack, 쓰면 g.
- **원가 단위 재계산**: 지금 K-* 브랜드 행은 단위 g 인데 `unit_cost` 에 1kg 봉지 가격이 들어 있어 **레시피 원가가 1000배 부풀어 있다.** 남는 행 `unit_cost` = **연결 단가 ÷ 환산비**(pack 가격 / 1000).
- 대상 쌍(실측, 레시피 줄 수): K-Gochujang 10 / K-Soy 10 / K-Mannani 6 / K-Kimchi 5 / K-Bulgogi 3 / K-Jjajang 3 / K-Sundubu 3 / K-Yukgaejang 3 / K-Jjamppong 2 / K-Soybean 1 / K-Chili Garlic 1 — 짝이 되는 `…1kg` 은 전부 레시피 0.
- **짝 없는 완제품**(Citron Salad · Oriental Salad · Kimchi for Soup · Soy Sauce for fish · 굿즈 3): 레시피에 안 쓰이고 사기만 하므로 Stock Item 하나(단위 pack)로 **이동**하고 GIT 프로덕트를 공급처로 연결.

**④ 열쇠 채움** — 활성 거울 전부에 출처 설정. **분류 순서는 프로덕트 먼저**:
   이름이 소유 브랜드의 활성 프로덕트와 일치(3단계, 후보 유일)하면 `source_brand_product_id` 만 채우고 **Stock Item 을 만들지 않는다.**
   아니면 Stock Item 붙임/생성.
   ⚠ 프로덕트가 브랜드에 닿는 길은 **둘**이다 — `brand_product_brands` 명시 연결, 그리고 **연결 행이 없는 프로덕트(전 브랜드 배포) → 소유자의 브랜드 전부**.
   후자를 빠뜨리면 `PRD-114/115`(MTP 컵·뚜껑)처럼 연결 행 0 인 프로덕트를 못 찾아 그 재료가 **꺼진 Stock Item 에 붙으려다** 가드에 걸린다(실제로 그랬다).

**⑤ 거울 이름·단위·카테고리 수정 API 403** (매장 재고 입력은 열어 둔다).

**⑥ 화면** — 공유 체크 · 레시피 선택기 · Shared Ingredients 제거 · F7 표시 살리기.

**⑦ Stock Items 내부 정리 — 같은 물질이 여러 줄인 것 (실측 15개 물질)**

*C. 중복이 아니다 — 합치지 말 것*
이름 본체가 같아 보여도 **크기·맛·규격이 상품을 구분**한다. 자동 판정기가 이것들을 같은 것으로 묶으므로 명시한다:

### 3-3. 손대지 않는 것 (정직하게 남긴다)
- **미확정 3건**: `303 Peeled Garlic (Bawang Putih Kopek)`(환산비 불명) · `157 Hotteok (삼립미니꿀호떡)`(팩당 개수 불명) · `Kimchi 169/142`(다른 상품 가능성). 전부 활성 유지, 이유를 목록에 남긴다.
- **brand 1 재료 63건(전부 비활성)** — 거울을 만들지 않는다. 그중 **21건**이 `inventory_transactions` 기록 1~3건씩을 갖고 있으나 **레시피·덧씌우기·발주 연결은 전부 0** 이므로 **이력 보존 목적으로 비활성 유지**(삭제 아님), **원장 기록 무접촉**. 21건은 전부 포장재 계열. with MIN Cafe 는 자기 소유 재료로 이미 돌아간다.
- **원장 57건 · 발주 이력** 무접촉.
- **매장 10 자기 소유 재료(1000번대)** 무접촉. 다만 그중 단위 규칙(§1-5) 위반이 실측됐다 —
  `Sliced Beef for Bulgogi` 가 매장 재료 **kg** / Stock Item **piece** 로 갈려 각각 같은 공급업체 상품에
  따로 연결돼 있고 환산비는 둘 다 1.0 이다. **매장 소유 행의 단위·환산비 정합은 후속**(이번 범위 밖).
- **가격 규칙을 새로 만들지 않는다.** 거울 `unit_cost` = Stock Item 원가(초기값 폴백). 매장 발주 단가를 GIT 판매가 참조로 바꾸는 것은 `TRADE_STRUCTURE.md` §5-1 개편에서 다룬다.
