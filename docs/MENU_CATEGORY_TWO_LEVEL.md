## 0. 실측한 지금 상태 (2026-10-11 개발서버)
- `categories`: 상위 칸 없음(1단). 이름은 매장 안에서 이미 겹치기 금지 — 만들기(POST /api/categories)·이름 바꾸기(PUT /:oldName, PUT /id/:id) 둘 다 거절. 비교는 대소문자 무시(utf8mb4_unicode_ci). 개발 DB 겹치는 이름 0건. → **D2 는 이미 지켜지고 있다. 새 검사 불필요, 회귀 검사만.**
- `products.category` = 카테고리 **이름** 문자열(개발 DB 140/140). 프론트(MenuContext)는 이를 카테고리 id 로 바꿔 쓴다.
- 🔒 POS(`POSTerminalPage.tsx` 1337행): 비활성 카테고리만 빼고, **메뉴가 0개인 카테고리도 탭으로 보인다**(새 카테고리 흐름 때문). 보호 파일이라 고치지 않는다.
- 🔒 KDS(`KitchenDisplayPage.tsx` 1014행)·🔒 `utils/stationEnrichment.js`: 메뉴의 카테고리 → 그 카테고리의 주방(kitchen_station_id). 상위 개념 없음.
- 브랜드 동기화(`brandMenuSyncService.ensureLocalCategory`): 매장 카테고리를 이름으로 찾거나 만든다(상위 칸 안 건드림).
- 모바일·키오스크 메뉴 카드: 이미지·이름·가격·SET 표시만. 설명·추천 표시 없음. `is_featured` 는 Featured 탭에만 쓰임.

## ① 구조 — 2단 카테고리

### 데이터
- `categories.parent_id` INT NULL 하나 추가(sync-database, 기존 행 전부 NULL = 지금과 같음). 새 표·새 목록 없음. [Fable]
- 규칙 (저장할 때 서버가 거절, 400):
  - 2단까지만 — 상위로 고른 카테고리가 이미 하위면 거절, 하위가 있는 카테고리를 다른 카테고리 밑으로 넣으면 거절. [Fable]
  - 자기 자신·다른 매장 카테고리를 상위로 고르면 거절. [Opus]
  - 이름 겹치기 금지 = 지금 규칙 그대로(상·하위 통틀어). [Fable · 이미 있음]
- 하위를 만들 때 주방(kitchen_station_id)이 비어 있으면 **상위의 주방을 미리 채워 저장**. 주방 배정 코드는 변경 0. [Fable]
- 상위를 지우려면 하위가 없어야 한다(있으면 400 «하위 카테고리를 먼저 옮기거나 지우세요»). [Opus]
- **카테고리는 «메뉴 칸» 아니면 «하위 칸» 둘 중 하나**(섞인 상위 금지). 하위 있는 카테고리에 메뉴 저장 → 400. 메뉴가 담긴 카테고리 밑에 하위 만들기 → «옮기기» 없이는 400. 규칙 검사는 서버 함수 한 곳(메뉴 저장·상위 변경·브랜드 동기화가 함께 씀). [Fable 2차 판정]
- 첫 하위를 만들 때 그 카테고리에 메뉴가 있으면 만들기 창에 «이 카테고리 메뉴 N개를 새 하위로 옮기기»(기본 켜짐) — 지금 «이름 바꾸기»가 하는 일괄 변경과 같은 방식. [Fable 2차 판정]

### 묶음 칸(하위 있는 상위) — 🔒 POS 무접촉 [Fable 2차 판정]
- 위 규칙으로 «하위 있는 상위 = 묶음 칸»이 고정(메뉴 개수로 흔들리지 않음).
- 화면 공용 메뉴 자료(`MenuContext`)가 POS·메뉴관리 선택·KDS 에 주는 목록에서 **하위가 있는 상위만** 뺀다. 카테고리 관리 화면만 전체(상·하위) 목록을 따로 받는다.
- 결과: **POS 는 하위가 평평한 탭**. POS 파일 변경 0. POS 2단 탭은 하지 않음(필요하면 나중 별도 건).
- 브랜드 동기화가 이름으로 찾은 매장 카테고리가 묶음 칸이면: 메뉴를 거기 넣지 않고 «Uncategorized» 처리 + 동기화 결과에 «카테고리 ‹이름›은 묶음 칸이라 넣지 못함» 남김(조용히 넣지도 버리지도 않음).
- 기기에 저장된 옛 카테고리 캐시(상위 칸 없음)를 첫 로드에서 서버 값으로 덮어쓰는지 확인.

### 시간대 노출
- 상위가 시간대로 숨김/흐리게면 그 하위도 같은 처리(모바일 메뉴 API 한 곳, `routes/mobile-public.js`). [Fable]

### 화면
- **카테고리 관리(RA)**: 카테고리 만들기/수정 창에 «상위 카테고리» 선택(없음 = 1단). 목록은 상위 아래에 하위를 들여쓰기로. 순서 바꾸기는 같은 상위 안에서.
- **메뉴 관리**: 메뉴의 카테고리 선택 목록에 하위를 «상위 › 하위» 로 표시(저장 값은 지금처럼 이름).
- **모바일·키오스크 메뉴**: 상위 탭/열 그대로. 하위가 있는 상위를 고르면 그 아래 **하위 알약 한 줄**(«전체» + 하위들, 기본 «전체» = 상위 직접 메뉴 + 하위 메뉴 전부). 하위 없는 상위는 지금과 똑같다(손가락 한 번 늘지 않음). [Fable 조건 ①]
- **POS·KDS·주방 인쇄**: 변경 0(위 «묶음 전용» 장치로).
- 브랜드 메뉴 카테고리 2단은 2차. K-DINE 매장 메뉴 무접촉. [Fable]

## ② 카드 내용 — 한 줄 문구 + 추천 마크

- `products.tagline` VARCHAR(80) NULL 하나 추가 — 목록 카드용 짧은 어필 문구. 지금 «설명»(긴 글, 상세용)과 별개. [Fable]
- 추천 마크 = 지금 있는 `is_featured`(Featured) 를 카드에 그린다. 새 칸 없음. [Fable]
- 메뉴 관리 편집 창: «한 줄 소개(목록에 보임, 80자)» 입력 + Featured 스위치 옆에 «분류당 1~3개만 권장» 안내 문구(강제 없음). [Fable]
- 모바일·키오스크 목록 카드: 이름 아래 한 줄 문구(넘치면 말줄임), 모서리에 추천 마크(텍스트 배지, 장식 이모지 금지 — 디자인 기준). 상세 화면 이름 아래에도 같은 문구·마크.
- 폰 화면은 문구·마크가 없는 메뉴면 지금과 픽셀 동일(스크린샷 비교로 확인).
- 번역: 메뉴 이름·설명과 같은 방식(지금 메뉴 이름에 번역 칸 없음 → 문구도 매장이 입력한 그대로).
- 브랜드 메뉴에서 내려온 메뉴: tagline 은 잠금 칸 아님(매장이 써도 됨). 브랜드 쪽 tagline 은 2차.
