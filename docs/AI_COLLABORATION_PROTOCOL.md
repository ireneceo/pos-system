# AI 협업 프로토콜

이 문서는 Claude Code와 Codex를 함께 사용하는 프로젝트에 복사해 적용할 수 있는 공통 운영 규칙이다.

## 역할

### Fable

기존 코드 조사, 개발기획, 요구사항 해석, 설계, 원인 판정, 복잡한 검증 기준과 최종 판단을 담당한다.

### Opus

Fable이 정한 설계를 바탕으로 핵심 기능을 구현한다. 구현 범위를 임의로 넓히지 않는다.

### Codex

보조 개발자로서 다음 작업만 담당한다.

- 명확히 지정된 단순·반복 수정
- 지정된 문구·번역·문서의 기계적 갱신
- 이미 정해진 명령의 실행과 장시간 작업 대기
- 자기 변경에 대한 빌드·테스트·정적 검증
- 전달받은 결과의 상태 파일 기록

Codex는 기존 코드 조사, 개발기획, 설계, 구조 결정, 주요 클래스·서비스·라우트·DB 모델 변경을 스스로 시작하지 않는다. 요구사항이 모호하거나 선택지가 있으면 작업을 멈추고 사용자에게 구체 지시를 요청한다.

## 도구별 독립 운영

사용자가 Codex를 선택한 세션에서는 Codex가 명확히 위임받은 작업을 수행하고 자기 작업을 검증한다. Fable·Opus로 자동 위임하거나 연결하지 않는다.

사용자가 Claude Code를 선택한 세션에서는 Fable·Opus의 기존 흐름을 따른다. Codex를 중간 검토자나 자동 대체자로 끼워 넣지 않는다.

파일과 기록은 공유하지만 세션과 역할은 공유하지 않는다. 한 번에 한 도구만 편집한다.

## Codex 작업 판정

Codex가 바로 처리할 수 있는 작업은 요구사항이 구체적이고, 설계 선택이 없고, 영향 범위가 작고, 되돌리기 쉬운 작업이다. 예: 지정된 문구 교체, 기존 번역 키 보완, 문서 기록, 지정된 검사 실행, 자기 변경의 빌드·테스트.

다음은 Codex가 임의로 처리하지 않는다: 새 기능 기획, UX·아키텍처 결정, 주요 구조 변경, 돈·주문·권한·인쇄·KDS 로직 변경, 운영 DB 수정, 배포 결정.

## 기록 규칙

공유 기록에는 실제 주체를 `[Claude Code]`, `[Codex]`, `[공동 검토]`로 표시한다. 기존 변경의 주체는 추측하지 않는다. 작업 전후 `git status`와 `git diff`를 확인하고, 미커밋 변경을 덮어쓰지 않는다.

## 세션 체크리스트

1. 현재 도구와 위임 범위를 확인한다.
2. 기존 미커밋 변경을 확인한다.
3. 한 번에 한 도구만 편집한다.
4. Codex는 자기 변경을 직접 검증한다.
5. 작업자·검증자를 기록한다.
6. 범위를 넘는 판단이 필요하면 중단하고 사용자에게 요청한다.
