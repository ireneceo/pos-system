## 그룹 1 — 브랜드/메뉴 데이터·관리

### 1-1. 🆕 브랜드메뉴 이름 한글 제거 (일괄 정리)
브랜드메뉴 126개 이름이 "한글 l English" 형식. 한글 제거 규칙 3가지(Irene 명시):
- **(a) 한글 바로 뒤 특수문자(`l`)** = "망고 크로플 l Mango Croffle" → `Mango Croffle` (한글+구분자 제거)
- **(b) 한글만 있는 것** = 한글 제거 (영문 없으면 → 확인 필요, 데이터 실측 후 개별 처리)
- **(c) 한글 뒤 바로 특수문자 아닌 것** = "후라이드 치킨 윙 16pcs l Fried…" → 선행 한글만 제거해 `16pcs…` 로 시작
- **주의:** 브랜드 이름 변경 → sync 로 매장 전파(lock_name 매장은 강제). **실행 전 dry-run 미리보기로 126개 before→after 보여주고 승인** 후 적용(엣지케이스 b 때문). 운영 데이터 작업.

### 1-2. ✅ 브랜드메뉴 순서변경 (이미 드래그 됨 — 안내 + discoverability 개선)
- **현재도 됨:** BrandMenusPage 정렬 드롭다운을 **"Menu order (manual)"** 로 바꾸면 카드 좌상단 핸들로 드래그 재정렬(`/api/brand-menus/reorder/bulk`). 기본값이 "Newest"라 드래그가 꺼져 보였음(안내문구는 이미 있음).
- **개선(◑):** 기본 정렬을 manual 로 하거나, 드래그 가능 상태를 더 눈에 띄게(핸들 강조/토글). 작은 UX.

### 1-3. ◑ RA가 브랜드메뉴에도 옵션 따로 추가·연결
- 브랜드가 보낸 메뉴여도 매장이 자기 옵션그룹을 추가/연결 가능해야. **백엔드 sync 는 이미 매장 자체옵션 보존**(merge — brandMenuSyncService 196-198). **확인 필요 = 매장 메뉴관리 UI(MenuManagementPage)에서 브랜드연결 상품 편집 시 옵션 추가가 막혀있는지/저장되는지.** (1-4 와 연관.)

### 1-4. 🐞 브랜드 잠금 메뉴 "View" 팝업 — 입력/수정은 되는데 저장이 안 됨 (UI 이상)
- 레스토랑에서 브랜드가 모든 필드 잠근 메뉴를 열면 **입력칸이 편집 가능한 것처럼 보이는데 저장이 안 됨.** → 잠금 시 읽기전용 표시(disabled + "브랜드 잠금" 안내)로 UI 정리, 또는 허용 필드만 편집 가능하게. **버그/혼동 수정.**

### 1-5. 🚀 세트 전파 영구수정 — 코드 완료, 배포만 남음
- **이미 함:** `brandMenuSyncService.js` 세트구성 항상미러 수정 = **커밋 완료(dev)**. 운영 데이터도 이미 동기화됨(thefire 3매장).
- **"재발방지"의 의미:** 지금 데이터는 맞음. 하지만 **운영 서버 코드엔 아직 옛 버그가 돎** → BG가 앞으로 세트를 또 편집하면 그 변경이 매장에 안 갈 수 있음. **이 영구수정이 /배포돼야** 앞으로 BG 편집이 자동으로 매장까지 감(=재발방지 완성). 배포 전이면 BG 세트편집 후 수동 재동기화 필요. (배포는 Irene "나중에".)
